# README 写作规范

状态：正式草案。本文规定仓库根 `README.md` 的**格式要求**，供后续改动与评审对照；README 的内容随产品演进更新，但其结构与写作口径以本规范为准。

## 1. 定位

README 是仓库的**门面与最小上手路径**，读者是第一次打开仓库的人（使用者与贡献者）。它回答三个问题：这是什么、怎么跑起来、用了谁的成果。它**不承担**决策论证与历史记录——那些属于 `docs/architecture/decision-checklist.md`、`docs/rfc/` 与 `docs/spec/`，README 只在需要时给链接。

## 2. 必须的章节与顺序

按下表顺序组织；除非章节无内容，否则不省略。

| 序号 | 章节 | 必含内容 |
| --- | --- | --- |
| 1 | 标题 + 一句话定位 | 中文名（英文名）与一句 `>` 引用式描述，一句话说清产品是什么 |
| 2 | 徽章 | CI 状态、许可证；可选平台 / 发布徽章，均须指向真实可访问的目标 |
| 3 | 简介 | 2–4 句：定位、组织模型、数据落在哪里（本机 / 云端） |
| 4 | 功能 | 8–12 条**单行**要点，动词开头；一条只讲一件事 |
| 5 | 技术栈 | 表格：层 / 选型（桌面壳、前端、后端、数据、包管理） |
| 6 | 环境要求 | 操作系统、运行时、Node / pnpm、Rust 工具链，并给出版本真相所在文件（如 `rust-toolchain.toml`） |
| 7 | 快速开始 | 可直接复制的安装与开发运行命令块 |
| 8 | 目录结构 | 顶层目录表 + Rust crate 表（各一行职责） |
| 9 | 配置 | 环境变量表：变量 / 作用 |
| 10 | 构建与发布 | 构建命令表；发布包形态与手动发布入口 |
| 11 | 持续集成 | CI 作业与它和本地钩子的关系（各一行） |
| 12 | 第三方组件 | 表格：组件 / 版本 / 许可 / 用途与分发方式；**必须包含 mpv 与 FFmpeg**（见第 4 节） |
| 13 | 文档 | 指向 `docs/` 各目录与关键规范 |
| 14 | 贡献 | Issue / PR、文本文件口径、提交前门禁 |
| 15 | 许可证 | 许可证名称与链接；随包分发的第三方 GPL 组件须在此说明再分发义务 |

## 3. 写作口径

- **只写事实**：能力、命令、路径、版本、链接。不写"为什么要这么做""当时怎么想的"——那类内容进决策清单或规范。
- **不啰嗦**：每条要点一行；一个事实只出现一次，不跨章节重复。篇幅预算约 **200 行以内**，超出时优先删解释、保留命令与表。
- **不写无关话语**：无寒暄、无口号、无"欢迎使用"式抒情；不列与上手无关的内部编号（D 编号只在确有必要指向决策时出现，且给链接）。
- **可执行**：所有命令块必须能照抄执行；路径与命令的真实来源是 `package.json` 的 scripts，改脚本时同步改 README。
- **版本写"来源"而非"数字"**：工具链与依赖版本优先写"见 `rust-toolchain.toml` / `packageManager` / `Cargo.toml`"，避免两处漂移；确需写具体版本时以仓库文件为准。
- **语言**：正文中文，术语、命令、代码、路径用英文原文；标题用短名词，不写成句子。
- **表格优先**：并列事实（命令、变量、组件、crate）用表格，不用长段落罗列。
- **链接有效**：外部链接指向项目官网或上游仓库，不指向二手页面。

## 4. 第三方组件与参考项目

- 第 12 节必须列出**实际随包分发或构建依赖**的第三方组件，并至少覆盖 **mpv** 与 **FFmpeg**：给出上游链接（`https://mpv.io/`、`https://ffmpeg.org/`）、版本、许可证、在项目中的用途与分发方式（随仓库 / 随包 / 构建期依赖）。
- 若实现**参考**了其他开源项目（例如 EPUB 排印参考 Readium CSS、foliate-js），在第 12 节末尾用一句话致谢并给链接，不与"依赖"混为一谈。
- 许可证信息必须与 `LICENSE` 和随包资产的实际许可一致；GPL 组件再分发义务在第 15 节点明。

## 5. 维护规则

- 功能、命令、环境要求、第三方组件、发布方式发生变化时，**同一次提交内**更新 README 对应章节。
- README 改动须通过 `pnpm check:encoding`（UTF-8 无 BOM、LF）与仓库既有门禁；README 不参与 `check:doc-status` 扫描（该门禁只扫 `docs/**`），因此不得在 README 里写未决状态措辞。
- 评审时对照本文第 2、3 节逐项检查：章节齐全、顺序正确、每节只放事实、无重复段落。
