# 控件标准（面板内部的 26 种宿主内置 UI 单元；插件不可注册控件）

状态：正式草案（**2026-09 标准化：schema 传输格式 / 宿主组件白名单 / 校验分级 / 受控渲染骨架已定稿并落地**，见「控件 schema 规范（第一版·已定稿）」）。本文规范**控件**——**面板内部的**标准 UI 单元（用户已确认方向，见 D44）。**2026-09 修订**：「浮动控件」这一插件控件类别**已取消**（D44/D49/D56）；"浮在布局之上的一层显示"改由蓝图 **`overlay`（浮层）容器**承载，其显隐由蓝图规则决定，浮层的内容就是面板。下文凡出现「浮动控件」处，一律按此口径理解为"浮层内容（面板）"。控件标准必须先于插件 UI 实现落地；插件不得创建自由 React 组件，也不得创建独立窗口（RFC 0004 决策 12）。

**注册权边界（RFC 0010 决策 2，2026-09）**：插件**可以**注册**面板**（`docs/spec/panel-standard.md`）与**蓝图节点类型**（`docs/spec/blueprint-node-standard.md` 第 2.3 节），**不可以**注册**控件**——26 种 `kind` 是**宿主内置白名单**（D62 不变），插件只能在**自己的面板内**按 schema **使用**它们（创建实例），不能新增、覆盖或改写控件类型。

**命名状态（2026-09 二次统一，RFC 0010 决策 1）**：RFC 0007 原用「控件（Control）」指绑定 dockview 面板的 UI 组件实例，与本标准的「控件」同名不同义；D46 曾把它改称「面板控件」。现 RFC 0010 **撤销「面板控件」这一叫法，退回「面板（Panel）」**，并把蓝图原「类（Class）」改称「**类目（Category）**」。于是三个词各自独占一个概念、不再混用：

| 词 | 指代 | 层级 | 谁可注册 |
| --- | --- | --- | --- |
| **面板（Panel）** | dockview 承载单元（仓库/查看器/媒体预览…） | 蓝图节点 `control`（枚举不变） | 宿主 13 个 + **插件可注册** |
| **控件（Control）** | 面板**内部**的标准 UI 单元（26 种） | 面板**渲染树** | **仅宿主**（D62） |
| **类目（Category）** | 面板内条目分类（原「类」） | 蓝图节点 `class`（枚举不变） | 宿主 |

**两棵树，别混**：蓝图**结构树**是 `面板 ⊃ 类目 ⊃ 对象`；控件在**面板渲染树**里（`面板 → 控件 schema`），**不是**蓝图节点。因此"面板下能挂什么"由面板的 `has_class` 决定（`docs/spec/panel-standard.md` 第 5.1 节），与控件类型无关。

全部改名均为**仅显示用语**变更：节点枚举值 `control` / `class`、字段名、库表、命令名与 i18n 键名一律不变（同 D46/D68 口径）。

**层级对齐（D51）**：蓝图侧**一个层 = 一张画布 = 一个界面（页面）**，层名可自定义且**层名即界面显示名**；一个蓝图控制**一个仓库**，跨层连接只允许**界面跳转**。本文的「界面」与蓝图的「层」是同一层概念（层的根节点即 `interface`）。

## 层级：界面为顶层，收纳面板；控件在面板内部

**界面（Interface）** 是**顶层容器**，对应"整个应用界面"；它同时是**页面**——**一个界面 = 一个页面**，是**后续多页面的基础**，蓝图行为可做**界面跳转**（RFC 0007 决策 1/3）。蓝图侧以 `interface` 节点表达。

**蓝图结构树**（RFC 0010 决策 1，`docs/spec/blueprint-node-standard.md`）：

```text
界面（顶层容器 / 页面，可多个，可互相跳转）
  │
  ├─ 布局块（区域/栏）  ← 与浮层 overlay【同级】
  │    ├─ 标签组
  │    │    └─ 面板（dockview 面板；蓝图节点 `control`）
  │    │         └─ 类目 → 对象
  │    └─ 面板（单面板直连）
  │         └─ 类目 → 对象
  │
  └─ 浮层 overlay（与布局块同级；层级/z 序**在布局块之上**，整体浮层覆盖）
       └─ 标签组 / 面板
```

**面板渲染树**（本文规范对象）：

```text
面板 → 控件（26 种 host kind，`kind` → 受信 React 组件）→ 数据绑定 / 事件回传
```

**注意两条容易读错的地方**：

1. **控件不是蓝图节点**：它不在上面的结构树里，只存在于**面板内部**。面板下挂的是**类目**（`class`），不是控件。
2. **面板下能否挂类目由面板自己声明**：看面板注册表的 `has_class`（`docs/spec/panel-standard.md` 第 5.1 节），不由控件类型决定。

**层级与 z 序**（自下而上）：**布局块 < 浮层**。两者都是界面的直接子级，**浮层整体盖在布局块之上**。（"显示高度更高"在本标准中一律指**层级/z 序**；浮层自身框体的像素高度另述，见"可定义外观"。）

- **界面**：顶层容器与页面；蓝图里以**层**表达（一个层 = 一张画布 = 一个界面，层名即界面显示名，D51），蓝图的 `interface` 节点是该层的根。**一个文档可有多个层**（多页面），层之间用**界面跳转**行为连接。界面收纳**结构层**（布局块 → 标签组 → 面板 → 类目 → 对象），并以**同级**方式持有**浮层（`overlay`）节点**；浮层本身是**容器**，可 contains 面板与标签组。
- **布局块 / 标签组 / 面板 / 类目 / 对象**：蓝图的结构层（RFC 0007 决策 1；术语见 RFC 0010 决策 1）。
- **控件**：本文规范的 UI 单元，由插件在**自己的面板内**按 schema 创建实例（**不是**蓝图节点，**不是**界面的直接子级，也**不能**由插件注册类型）。
- **浮层（`overlay`）**：与**布局块同级**的界面子级，z 序**在布局块之上**；整体浮层，不归属某个面板的结构子树，也不贴附某个控件；它是**容器**（内容为面板/标签组）。
- 界面节点不直接持有控件，也**不参与显隐/收起求值**；跳转由行为节点表达。

## 术语分层

| 术语 | 含义 | 是否可持久化 | 当前实现锚点 |
| --- | --- | --- | --- |
| **层（Layer）** | 蓝图内部的画布：**一个层 = 一张画布 = 一个界面（页面）**；层名可自定义且即界面显示名 | 是（蓝图文档内 `layers[]`，**已实现**） | RFC 0007「分层（Layer）」 |
| **界面（Interface）** | **顶层容器**，也是**页面**：一个界面 = 一个页面；界面是**后续多页面的基础**，行为可做**界面跳转**。以**同级**方式持有**布局块**与**浮层** | 是（蓝图节点，按仓库） | 蓝图 `interface` 节点（RFC 0007） |
| **面板（Panel）** | dockview 承载单元：标签页、可拖拽停靠、可浮动、可独立窗口；蓝图节点枚举 `control`（**显示名已由「面板控件」退回「面板」**，RFC 0010 决策 1） | 是（`panel_layouts`，按仓库） | `packages/config/src/panels.ts`、`apps/desktop/src/app_ui/core/panelRegistry.tsx`、`docs/spec/panel-standard.md` |
| **控件（Control）** | 宿主提供的标准 UI 单元（26 种），插件在**自己的面板内**按 schema 创建实例；**本文规范对象**，**不可由插件注册**（D62） | schema 是渲染期输入（**不落库**，D61） | `packages/config/src/controlRegistry.ts`、`crates/hp-core/src/control_types.rs` |
| **类目（Category）** | 蓝图里的**节点类型**（`class`，显示名原为「类」）：面板内部条目分类（image/video/audio），受面板 `has_class` 约束 | 是（蓝图节点） | `docs/spec/blueprint-node-standard.md`、`docs/spec/panel-standard.md` 第 5.1 节 |
| **浮层（Overlay）** | 蓝图里的**节点类型**（`overlay`，D50，**已实现**）：与布局块同级、是**容器**（contains 面板/标签组），承载显隐、相对定位、框体尺寸与外观档位 | 是（蓝图节点） | RFC 0007「浮层节点」 |
| ~~**浮动控件（Floating Control）**~~ | **已取消（2026-09，D44/D56）**：该插件控件类别不再存在；原"与布局块同级、显示在布局块之上"的结论**原样适用于蓝图 `overlay` 浮层容器** | — | 由 `overlay` 承载 |
| **独立窗口** | Tauri 多窗口 | 是 | 已存在（标签页右键「独立」） |

五条判据（避免与已有概念混淆）：

1. 界面**不是**面板：界面是页面级容器，下辖布局块/标签组/面板；面板是界面内的 dockview 承载单元。
2. 控件**不是**面板：控件是面板**内部**的 UI 单元，插件不能借控件创建标签页、改变布局分组或创建窗口；**界面跳转由蓝图行为决定**，插件只能触发事件，不能直接跳转界面。
3. 浮层**不是**独立窗口：它属于宿主窗口内部的一层叠加显示，随宿主窗口的显示与销毁而存在。
4. **面板不是控件、也不是另一种控件**：面板是**可注册对象**（宿主 13 个 + 插件可注册），控件是**面板内部的渲染单元**且**仅宿主可注册**。D46 曾把面板叫「面板控件」，该叫法已由 RFC 0010 撤销——**不要把面板读成控件的一种**。
5. **浮层与布局块同级**：两者都是界面的直接子级；浮层**显示在布局块之上**（整体浮层覆盖），不是某个布局块/面板的子节点，也不是"贴在某个控件旁边的挂件"；浮层的**内容**（它 `contains` 的面板/标签组）才是它的子树。
6. **控件不是蓝图节点**：蓝图结构树里没有控件；面板下挂的是**类目**（`class`），能否挂由面板的 `has_class` 声明（`docs/spec/panel-standard.md` 第 5.1 节）。

## 控件标准

### 定位

- 控件是**受控组件**：插件只提供数据与 schema，宿主负责映射到受信任的 React 组件集合并渲染（RFC 0004 决策 12）。
- 控件的**外观与行为**由宿主定义；插件只能在标准允许的属性范围内调整。
- 控件只能读写经宿主 API 授权的数据；不得直接触碰数据库、文件系统或 DOM。

### 分类（第一版）

| 类别 | 用途 | 是否可由插件创建 |
| --- | --- | --- |
| 布局容器 | 行、列、分栏、可折叠区 | 是 |
| 展示 | 文本、图标、图像、进度条、键值列表 | 是 |
| 输入 | 按钮、开关、输入框、下拉、滑块、数值步进 | 是 |
| 集合 | 列表、树、表格、标签链、缩略图网格 | 是 |
| 反馈 | 状态条、提示、空态占位 | 是 |
| ~~**浮动控件**~~ | ~~与布局块同级、显示高度在其**之上**的浮层附属显示~~ → **已取消（2026-09）**：不再作为插件可创建的控件类别；浮层由蓝图 `overlay` 容器承载，内容为**面板** | 否（改由蓝图声明） |

### 通用属性（第一版）

- `id`：控件在所属面板内的唯一标识。
- `kind`：控件类别 + 具体类型（宿主白名单内）。
- `visible` / `enabled`：显隐与可用状态。
- `class`：按 `media_type` 的**类目**（图像/视频/音频），与 RFC 0007 / RFC 0010 的类目语义一致。
- `size`：由所属布局决定时不得由插件写死像素；插件只能给建议值。
- `i18n`：所有文字必须走 i18n 键（D27），插件不得内联系统文字。

## 浮层（原「浮动控件」；2026-09 用户取消浮动控件概念）

> **术语变更（2026-09）**：「浮动控件」这一**插件可创建的控件类别已取消**。原来由它承载的"浮在布局之上的一层显示"改由**蓝图的 `overlay`（浮层）容器**表达；浮层的内容**就是面板**（可含标签组）。因此本节保留的只是"浮层容器"的规范，插件不再声明"浮动控件 schema"。

### 定义

浮层是**与布局块同级**的界面子级，**显示高度在布局块之上**：它以整体浮层的形式盖在布局块（及其中的标签组、面板）之上，用于承载附属信息与轻量交互。它的内容由蓝图 `overlay` 节点 `contains` 的**面板/标签组**决定。

挂载与显示（关键）：

- **同级**：浮层与布局块并列，都是界面的直接子级；**不是**布局块的子节点，**不是**面板的子节点。
- **显示高度更高**：z 序为 布局块 < 浮层，因此**浮层整体盖在布局块之上**（覆盖该界面内的布局区域，而不是只贴在某个控件旁边）。
- 因此：**结构上同级、呈现上更高**——两句描述并不矛盾，前者是归属，后者是显示层级。

**明确不是**：

- 不是独立窗口（不创建 Tauri 窗口，不出现在任务栏）。
- 不是 dockview 面板（不参与停靠、分组、标签页，不进入布局网格）——注意：**浮层的内容**是面板，它们仍是 dockview 面板，只是以浮动方式显示。
- 不是某个布局块/面板的子元素（不随其显隐、收起而整体消失）。
- 不是模态对话框（除非宿主明确提供模态变体）。

### 可定义外观（档位由蓝图 `overlay` 节点声明）

| 属性 | 含义 | 约束 |
| --- | --- | --- |
| 圆角 | 四角圆角半径 | **只能取宿主设计 token 档位**（蓝图字段 `radius`：`none`/`sm`/`md`/`lg`），不允许任意像素 |
| 阴影 | 阴影层级 | 取宿主定义层级（蓝图字段 `shadow`：`none` / `sm` / `md` / `lg`） |
| 标签隐藏 | 隐藏浮层自带标签/标题，仅显示内容 | 布尔（蓝图字段 `hide_label`） |
| 边距 / 内边距 | 与界面边缘或布局块边界的内缩 | 取 token 档位 |
| 背景 | 背景层级 | 取宿主主题 token（浅色/深色自动适配） |
| 尺寸 | 浮层自身的框体宽×高（**不是** z 序） | **由蓝图 `overlay.size`（px）声明**：不写 = 默认最小 `240×160`，小于最小值按最小值夹紧，非正数/超 10000 为硬错误；**不占布局网格高度**，不挤压布局块；插件不得写死尺寸 |
| 层级（z 序） | 与布局块的叠放关系 | 固定 **布局块 < 浮层**；同界面内多个浮层按 `overlay.height`（1–10，值大者在上）排序 |

设计 token 的权威来源是 `packages/ui`；插件与蓝图都不得引入自定义配色或写死像素，以保证浅色/深色主题一致。

### 定位与层级

- **归属**：与**布局块同级**，由界面（页面）声明与持有；**不挂在面板之下**，也不属于任何布局块的结构子树。浮层的内容（`contains` 的面板/标签组）才是它的子树。
- **定位**：以**界面**（宿主窗口内容区）为参照系；蓝图浮层节点声明 **3×3 井字锚点**（`anchor`，缺省居中）与**双模式偏移**（`offset_x`/`offset_y`：`|v| ≤ 1` = 界面宽/高的比例，`|v| > 1` = 像素，可为负），宿主按"锚点对齐 → 叠加偏移 → **越界贴边收拢**"计算实际坐标（纯函数 `resolveOverlayPosition` 在 `packages/config`）。**不是**任意像素定位：**像素尺寸只由蓝图 `overlay.size` 设定**（默认最小 240×160），插件无权声明定位或尺寸。
- **z 序**：布局块 < 浮层；同一**界面**内的多个浮层按 `overlay.height`（1–10，值大者在上）叠放。层级不得跨越界面或窗口。
- **裁剪**：浮层不得溢出宿主窗口；越界时由宿主贴边收拢。
- **与布局的关系**：浮层**不参与布局网格**，不占布局块的空间、不改布局持久化；显隐变化只影响覆盖，不影响布局块自身的尺寸与位置。

### 生命周期与持久化

- 浮层的显隐**初始值**由蓝图的 `overlay` 节点承载（`overlay.visible`，D50），运行期由蓝图规则显隐；**不写入 `panel_layouts`**，也不改变布局块自身的尺寸与位置（不占布局网格）。
- 因与布局块同级，浮层**不随某个面板或某个布局块关闭/收起而销毁**：离开所属界面（或界面不可见）时隐藏，回到该界面时按声明恢复。
- **界面跳转**：切换页面时，上一界面的浮层随之隐藏（离开该界面），目标界面的浮层按自身声明显示；跨界面叠加不予支持。
- 蓝图控制的是**浮层是否显示**（`overlay` 节点 + 显隐动作）；**浮层本身是容器**（2026-09 用户修订，D50）：`interface --contains--> overlay --contains--> {面板, 标签组}`，即"浮层里放哪些面板"由**蓝图**声明；而**这些面板长什么样、能被插件怎么用**仍由本标准的 schema 与宿主白名单决定（插件不因此获得创建自由组件的权限）。
- **定位、尺寸与外观由蓝图 `overlay` 节点声明**：`anchor`（3×3 井字，缺省居中）+ `offset_x`/`offset_y`（`|v| ≤ 1` = 界面宽/高比例，`|v| > 1` = 像素）、`size`（宽×高 px，**不写 = 默认最小 240×160**，小于最小值夹紧）、`shadow`/`radius`（none/sm/md/lg）、`hide_label`；**实际像素外观取本文档与 `packages/ui` 的设计 token**，插件不得写死像素或自定义配色（尺寸是使用者对浮层框体的显式设定，属例外）。`overlay` 节点已实现（校验 + 画布端口 + 属性面板 + 引擎显隐动作 + 定位/尺寸纯函数 + 装载/套用布局/切层时的**初始显隐对账**）。
- **连接是显示的前提**：只有 `界面 --contains--> 浮层` 才表示该浮层属于本页；断开连接 = 未接通，运行时会收起该浮层且不再响应显示动作（详见 RFC 0007「浮层节点」）。
- 第一版同一**界面**内同时可见的浮层数量应由宿主限制，避免整屏遮挡。

### 能力与授权

- **浮层内容用面板承载**：创建面板需要 `ui.panel` 能力（随仓库启用默认授予）；浮层与布局块同级，但仓库上下文与面板一致，按当前仓库校验。**「浮动控件」类别已取消（2026-09），不再有需要绑定的 `control_id`。**
- **显隐与叠层（D50/D57）**：是否显示由蓝图规则决定（插件不能直接显隐浮层）；浮层之间的叠放由 `overlay.height`（**1–10，默认 1，值大者在上**）决定，**不是像素高度**。
- 浮层只是显示层：它不新增能力，**不得**成为绕过 `repo.read` / `repo.write` / `fs.*` 授权的通道。
- 浮层内面板的交互若触发写操作，仍按对应能力在该仓库单独授权校验。

## 插件与宿主的职责边界

| 事项 | 插件 | 宿主 |
| --- | --- | --- |
| **注册控件类型** | **不能**（26 种 `kind` 是宿主内置白名单，D62；RFC 0010 决策 2） | 持有白名单与类型注册表；拒绝白名单外的 `kind` |
| **注册面板 / 蓝图节点类型** | **可以**（贡献点 `panel` / `blueprintNode`，RFC 0010 决策 2/5/6） | 解析、校验、查表；强制 `plugin.<plugin_id>.<local_id>` 命名空间 |
| 声明控件 | 只给 schema 与数据 | 解析、校验、映射到受信组件 |
| 创建/销毁 | 只能请求 | 执行，并在离开界面或界面不可见时隐藏，**不随面板关闭而销毁** |
| 外观 | 只能选 token 档位 | 决定最终渲染与主题适配 |
| 定位与层级 | **不能**声明浮层定位（浮层定位由蓝图 `overlay` 节点声明） | 计算实际坐标、裁剪、层级排序（布局块 < 浮层） |
| 数据 | 经宿主 API 查询 | 能力校验与仓库上下文注入 |
| i18n | 提供键 | 渲染文字 |

宿主拒绝规则：

- schema 含白名单外的控件类型：拒绝渲染并记录事件。
- 蓝图声明的浮层锚点/偏移/尺寸非法（枚举外、非正数、超上限）：校验层报硬错误，小尺寸按最小值夹紧。
- 浮层试图跨界面/跨窗口叠加：拒绝创建。
- 插件试图指定任意坐标、任意样式、任意文字：忽略并记录。

## 控件 schema 规范（第一版·已定稿）

> 本节是「落地顺序」第 4–5 步的落地文本：**schema 传输格式、宿主组件白名单、校验分级**。文档是权威描述，代码里的权威实现是 `crates/hp-core/src/control_types.rs`（取值域与类型注册表）+ `control.rs`（结构、解析与校验）；前端 `packages/config/src/controlKinds.ts`（取值域）+ `controlRegistry.ts`（同一份注册表）+ `control.ts`（类型、解析层校验、事件载荷）与之逐项对齐，由 `pnpm check:controls` 守住一致性。

### 1. 定位与版本

- 控件 schema 是**纯数据**（JSON），不含代码、样式表、像素或任意表达式。插件只能声明"要一个什么控件、显示什么文字、绑哪些数据、发哪些事件"。
- 版本字段 `api_version`：与**宿主 API 版本**同源（`HOST_API_VERSION`，当前 `1`）。宿主只接受 `api_version <= 当前`；高于当前即拒绝（同蓝图版本闸门口径：`>` 才报错，`<` 走兼容解析）。
- schema **不落库**：面板布局仍由 `panel_layouts` 承载（D1/D53），控件 schema 是渲染期的输入，不是持久化结构。

### 2. 交付通道（运行时查询）

- manifest **只声明面板与贡献点**（`contributions` 里的 `panel`/`viewer`，见 `docs/spec/plugin-standard.md`），控件树由宿主在**需要渲染时**向插件查询。
- 通道按运行形态统一为一次"取面板 schema"的调用，插件侧不得区分：
  - `external-process`：宿主经插件子进程的 JSON-RPC 请求（请求名 `ui.panel.schema`，参数 `{ panel_id, api_version }`）；
  - `wasm`：宿主经受控导入函数取回（同一请求名，参数以线性内存中的 JSON 传递）；
  - `dynamic-library`：宿主经版本化结构体 ABI 调用。
- 宿主侧约束：单次查询**超时**（默认 2s）、**输出字节上限**（默认 256 KiB）、失败即该面板渲染为**错误态控件**（`empty` 的 `reason` 变体）并广播 `plugin.error`，不得阻塞其它面板。
- 查询结果按 `(plugin_id, panel_id, plugin_version)` 缓存；插件重载或版本变化即失效。
- **取数通道（第 5 节 `bind` 的数据来源）是**与 schema **并列**的第二条调用，请求名
  **`ui.panel.query`**，参数 `{ panel_id, api_version, selection?, queries }`：
  - `queries` 是**该面板全部 `bind`**（含 `visible_when` 引用的查询名）的数组，
    元素为 `{ key, name, kind, args? }`；**一次问完**（`external-process` 每次调用都要起
    一个进程，进程启动是主要成本）；同一 `{kind}:{name}` 只出现一次。
  - `key` 由**宿主**构造，恒为 `"{kind}:{name}"`——它与前端数据快照的查键
    （`apps/desktop/src/app_ui/shared/control/controlData.ts` 的 `makeControlDataSnapshot`）
    **逐字一致**；插件按 `key` 回填 `result.results`，宿主不做猜测映射。
  - `selection` 是 `{ file_id }`，**无选中项时整个字段缺省**（不是空对象）；
    宿主只把标量身份交给插件，不把仓库数据搬进 UI 进程。
  - 超时与字节上限**与 schema 同口径**（2s / 256 KiB）；失败同样是该面板渲染错误态控件
    并广播 `plugin.error`。
  - **取数结果不缓存**：数据的陈旧风险与 schema 不同（schema 随插件版本变化即可失效，
    数据随时会变），因此每次面板挂载 / 刷新都重查。插件**未返回**某个 `key` 不是错误，
    按"空结果"渲染空态。

> **落地状态（2026-09）**：`external-process` 通道**已落地**，权威实现在
> `crates/hp-plugin-host/src/channel.rs`（请求名常量 `PANEL_SCHEMA_REQUEST`、超时
> `SCHEMA_QUERY_TIMEOUT` = 2s、上限 `SCHEMA_MAX_BYTES` = 256 KiB、缓存
> `PanelSchemaCache`）。桥接命令是 `plugin.panelSchema`（`apps/desktop/src-tauri/src/commands/plugin.rs`），
> 失败时发射 `plugin.error`。两条**已定口径的实现取舍**：
>
> 1. **一次一问一答**：每次查询起一个子进程，读到第一行非空输出后立即收尾（杀掉并回收），
>    不做跨查询的常驻进程——因此没有"上次 play 之后才重建"这类时序状态，也不会因面板多开
>    而泄漏句柄。常驻进程与重启退避/不健康标记属 `external-process` **监督**（插件标准第 10 节），
>    仍待实现。
> 2. **只缓存成功**：失败（超时/超限/协议错）不入缓存，否则一次瞬时故障会被永久钉住。
>    失效靠键本身（含 `plugin_version`）+ `PanelSchemaCache::invalidate_plugin`。
>
> `wasm` 与 `dynamic-library` 两条通道仍**未接入**（各自依赖 `wasmi` 与版本化结构体 ABI）。
> 示例插件包的 `entry`（`bin/hello.exe`）是占位路径（产物不入库），因此装示例包会如实走到
> 「插件入口不存在」的错误态；联调方式见 `plugins/examples/hello/bin/README.md`。

### 3. schema 的 JSON 形态

```jsonc
{
  "api_version": 1,
  "panel_id": "palette.panel",          // 必须与 manifest 声明的面板 id 一致
  "root": {
    "id": "root",
    "kind": "column",
    "gap": "md",
    "children": [
      { "id": "title", "kind": "text", "text_key": "palette.title", "variant": "heading" },
      {
        "id": "colors",
        "kind": "thumbGrid",
        "bind": { "kind": "panel", "name": "colors" },
        "item_text": "hex",
        "on": { "double_click": "apply_color" }   // 事件名 → 插件声明的事件 id
      },
      {
        "id": "hint",
        "kind": "empty",
        "text_key": "palette.empty",
        "variant": "empty",
        "visible_when": { "kind": "panel", "name": "count", "test": "zero" }
      }
    ]
  }
}
```

- **节点通用字段**：`id`（面板内唯一、非空、`^[a-z][a-z0-9_]{0,63}$`）、`kind`（白名单，见第 4 节）、`visible`（默认 `true`）、`enabled`（默认 `true`）、`text_key`（i18n 键，D27）。
- **容器节点**额外带 `children`（数组）；**叶子节点**带 `children` 为非空即硬错误。
- **文字只用 `text_key`**：插件不得内联系统文字（D27）；`text_key` 由插件在自己的语言资源里提供，宿主按当前语言取。
- **紧凑写法**：`kind` 取具体类型（枚举值即 `kind`），不另设 `category` 字段——类别由第 4 节的定义表推导，避免两处口径。

### 4. 控件类型白名单（宿主内置枚举）

**第一版共 26 种**，全部由宿主渲染，插件**不能**新增控件类型（不开放自定义 `kind`）。列名含义：`容器` = 是否可带 `children`；`专属字段` = 该类型允许的额外字段（通用字段见第 3 节）；`事件` = 允许在 `on` 里声明的事件名。

| 类别 | `kind` | 用途 | 容器 | 专属字段 | 事件 |
| --- | --- | --- | --- | --- | --- |
| 布局容器 | `row` | 水平排列 | 是 | `gap` / `align` | — |
| 布局容器 | `column` | 垂直排列 | 是 | `gap` / `align` | — |
| 布局容器 | `panel` | 带边框/标题的区块 | 是 | `title_key` / `bordered` | — |
| 布局容器 | `section` | 可折叠区 | 是 | `title_key` / `collapsed` | `toggle` |
| 布局容器 | `spacer` | 占位撑开 | 否 | — | — |
| 展示 | `text` | 文本（可选 i18n + 数据绑定） | 否 | `text` / `variant`（`body`/`dim`/`heading`/`code`） | — |
| 展示 | `icon` | 图标（宿主图标集） | 否 | `icon` | — |
| 展示 | `image` | 图像（缩略图/预览 URL） | 否 | `fit`（`contain`/`cover`） | `click` |
| 展示 | `progress` | 进度条 | 否 | `max`（默认 1） | — |
| 展示 | `keyValue` | 键值列表 | 否 | — | — |
| 输入 | `button` | 按钮 | 否 | `variant`（`default`/`primary`/`danger`） | `click` / `double_click` |
| 输入 | `switch` | 开关 | 否 | — | `value_change` |
| 输入 | `textInput` | 单行输入 | 否 | `placeholder_key` / `multiline` | `value_change` / `submit` |
| 输入 | `numberInput` | 数值步进 | 否 | `min` / `max` / `step` | `value_change` |
| 输入 | `select` | 下拉（选项来自绑定） | 否 | `options_kind`（`static`/`bound`） | `value_change` |
| 输入 | `slider` | 滑块 | 否 | `min` / `max` / `step` | `value_change` |
| 输入 | `checkbox` | 复选 | 否 | — | `value_change` |
| 集合 | `list` | 列表 | 否 | `item_text` | `click` / `double_click` / `selection_change` |
| 集合 | `tree` | 树 | 否 | `item_text` | `click` / `double_click` / `selection_change` |
| 集合 | `table` | 表格 | 否 | `columns`（列 key 数组，≤ 8 列） | `click` / `double_click` / `selection_change` |
| 集合 | `tagChain` | 标签链（只读展示） | 否 | — | — |
| 集合 | `thumbGrid` | 缩略图网格 | 否 | `item_text`（`none`/`name`/`hex`） | `click` / `double_click` / `selection_change` |
| 反馈 | `status` | 状态条 | 否 | `variant`（`info`/`ok`/`warn`/`error`） | — |
| 反馈 | `notice` | 提示块（标题 + 文本） | 是 | `variant` | — |
| 反馈 | `empty` | 空态占位 | 否 | `variant`（`empty`/`loading`/`error`） | `click`（如"重试"） |
| 反馈 | `divider` | 分隔线 | 否 | — | — |

- **`align` / `gap`**：`gap` ∈ `none`/`sm`/`md`/`lg`（宿主 token，不写像素）；`align` ∈ `start`/`center`/`end`/`stretch`。
- **`image` / 集合类的数据来源只能是 `bind`**（第 5 节），插件不能直接给图片字节或绝对路径；宿主按自身缓存协议转成可显示的句柄。
- **`icon`** 只接受宿主图标集里的名字，白名单外即拒绝（避免插件塞任意资源）。
- 一版**不提供**：模态确认框、右键菜单定义、拖拽排序、自定义渲染钩子、任意 CSS/像素（与本节开头"明确不做"一致）。
- **「有无类目」不是控件的字段**：控件**不声明**"能否挂类目""对应哪个蓝图节点"——这两项是**面板**的声明参数（`has_class` / `blueprint_node`，见 `docs/spec/panel-standard.md` 第 5.1、5.2 节）。控件与蓝图的关系是**间接**的：蓝图管的是**面板**（`control` 节点）与**类目**（`class` 节点），控件只在面板**内部**渲染（RFC 0010 决策 1/4）。
- **本章是封闭白名单**：26 种 `kind` 全部由宿主实现与渲染；插件**不能**注册新 `kind`（RFC 0010 决策 2）。新增 `kind` 必须同时改 Rust 注册表、前端注册表、渲染映射、覆盖清单、本文档与 `pnpm check:controls`（见「验证」）。

### 5. 数据绑定（`bind`）

控件的数据**只能**来自宿主 API 的受控查询，不允许插件内联大块数据（避免把仓库数据搬进 UI 进程）：

```jsonc
{ "kind": "panel", "name": "colors", "args": { "max": 12 } }
```

- `kind`：`panel`（插件自己面板的作用域数据，由插件在宿主侧注册的只读查询名提供）/ `selection`（当前选中文件）/ `repo`（仓库只读信息）。第一版**只开放 `panel` 与 `selection`**，`repo` 需 `repo.read` 能力且列为开放点。
- `name`：查询名，必须是插件 manifest 声明过的名字（未声明即硬错误）。
- `args`：可选，**标量键值**（string/number/bool），不接受嵌套表达式。
- **`visible_when`**：可选的显隐谓词，`{ "kind": "panel", "name": "...", "test": "zero"|"empty"|"truthy"|"exists" }`。第一版仅这四个谓词，**不接受任意表达式**（与 D32「不进通用可视化脚本」同口径）。

> **落地状态（2026-09，第 4 轮补入）**：`panel` / `selection` 两种 `kind` 的**取数通道已落地**。
>
> 1. **请求名与形状**：`ui.panel.query`（第 2 节），一次带该面板全部 `bind`；宿主构造
>    快照键 `"{kind}:{name}"`，插件按 `key` 回填。权威实现在
>    `crates/hp-plugin-host/src/channel.rs`（`PANEL_QUERY_REQUEST` / `PanelQueryParams` /
>    `query_panel_data`）。
> 2. **宿主命令**：`plugin.panelData`（`apps/desktop/src-tauri/src/commands/plugin_panel_data.rs`），
>    入参 `{ repoId, panelId, selectedFileId?, binds }`。**fail-closed**：`bind.name` 必须在
>    插件 manifest 的 `data_queries` 里声明过（未声明即硬错误），`bind.kind` 是闭集
>    `panel` / `selection`（`repo` 仍是开放点，第一版拒绝）。
> 3. **前端接线**：`PluginPanelHost` 在 schema **通过业务级校验后**才取数（校验不过时界面
>    渲染错误态，白起一次插件进程没有意义）；收集逻辑在
>    `apps/desktop/src/app_ui/shared/control/controlBinds.ts`，**`bind` 与 `visible_when`
>    都收**（谓词也要数据，否则永远按"结果缺失"求值）。
> 4. **失败降级**：取数失败**不**把整面板打成错误态——schema 是好的、只是这一次没数据，
>    按本节的"绑定为空即渲染空态"处理，原因留在控制台；命令级失败（未启用/无归属/入口
>    缺失/超时/超限）仍走 `plugin.error` + 错误态。
> 5. **范围边界**：**不做**单条结果与 manifest `returns`（rows/object/scalar）的匹配校验
>    ——`PanelOwner` 目前只带查询**名**，扩它属于另一处改动；留待需要时一并做。

### 6. 事件回传（声明式 + 固定谓词表）

- `on` 是**事件名 → 事件 id** 的映射（事件 id 由插件在 manifest 的贡献点里声明）：`{ "click": "apply_color" }`。
- 允许的事件名固定为宿主谓词表：`click` / `double_click` / `selection_change` / `value_change` / `submit` / `toggle`（`cancel` 留给后续模态变体）。
- 回传载荷由**宿主**统一构造，插件不得自定义结构：
  `{ panel_id, control_id, event, value?, target? }`，其中 `value` 是控件的当前值（`textInput` 的文本、`switch` 的布尔、`select` 的选中值、`slider` 的数值），`target` 是集合类控件的选中项 id。
- 回传链：控件事件 → 宿主命令（`plugin.{pluginId}.{eventId}`）→ 插件；**同时**作为蓝图事件源上报给 `BlueprintEngine`（与 `MediaPreviewPanel` 的单击/双击同一条链），于是"控件被点击 → 蓝图动作"由**蓝图规则**决定，插件不直接操作显隐或跳转（D44/D48）。
- 未声明在 `on` 里的事件，控件交互不产生任何回传（宿主记录一次忽略事件）。

> **落地状态（2026-09）**：**事件 → 插件**与**作为蓝图事件源上报**两段都已落地。
>
> 1. **命令形态**：本节的回传链写的是字面命令名 `plugin.{pluginId}.{eventId}`，它要求
>    **动态注册**，而 Tauri 命令是**静态注册**的。落地时拆成两段——「前端 → 宿主」用一条
>    **通用**宿主命令 `plugin.controlEvent`（`apps/desktop/src-tauri/src/commands/plugin.rs:845`），
>    「宿主 → 插件」仍发**本节的字面方法名**（`crates/hp-plugin-host/src/channel.rs:52`）。
>    **插件侧看到的协议与本节一致**，偏差只落在宿主命令这一层，且已登记进
>    `docs/spec/commands-events.md` §3.11。
> 2. **载荷**：插件侧参数就是本节那条 `{ panel_id, control_id, event, value?, target? }`
>    ——**事件 id 由方法名承载**，不进载荷，因此没有扩展结构。
> 3. **fail-closed**：事件名取宿主谓词表（`cancel` 不在表内，留给后续模态变体）；
>    事件 id 必须在 manifest 的 `events` 里声明过；`value` 只收标量。未声明在 `on` 里的
>    事件不会到达宿主命令（调用方先判映射，缺失即记一次忽略）。
> 4. **交付代价**：沿用 `external-process` 的一次一问一答，**每次点击起一个插件进程**；
>    常驻进程与重启退避/不健康标记（`external-process` 监督）仍未实现——这里不假装
>    已经做了监督。
> 5. **同时作为蓝图事件源上报**（本节第 4 条「回传链」的后半）：控件的单击 / 双击 / 选中变化
>    会以同名触发词（`BLUEPRINT_TRIGGERS` = `click` / `double_click` / `selection_change`）
>    上报 `BlueprintEngine`，即"控件被点击 → 蓝图动作"由**蓝图规则**决定，插件不直接操作
>    显隐或跳转。
>    - **只有这三个**：其余三个事件名（`value_change` / `submit` / `toggle`）在蓝图触发词表里
>      **没有对应词**，只回传插件——替它们发明触发词会扩宽蓝图契约。
>    - **匹配口径**：上报带 `panelId`，`control` 节点按**既有**的 `panel_id` 字段匹配
>      （`BlueprintTargetRef.panelId`）。这是**选择加入式**的——**不带** `panelId` 的上报
>      （媒体条目链路）行为不变，既有蓝图**零回归**。
>    - **`controlId` 不参与匹配**，且**有意不新增**承载"某个具体控件实例"的蓝图字段：
>      那正是 2026-09 已取消的「浮动控件」绑定（D56，见
>      `docs/architecture/decision-checklist.md:63`）。字段仍按规范载荷原样带回（诊断用），
>      引擎忽略它。
>
> 门禁：`pnpm check:controls` 新增 5 项断言（事件映射按控件 id 收集、事件名 → 事件 id
> 解析、插件侧方法名是契约字面名、命令已实现并注册且 id 必须声明过、前端 `emit` 不再置空）；
> `pnpm check:blueprint-engine` 新增 2 项（带 `panelId` 只命中同 `panel_id` 的 `control` 节点、
> 不带 `panelId` 时保持既有行为）。

### 7. 校验分级（与蓝图同一口径）

**解析层（前端 `parseControlSchema`，拒绝渲染）**：

- 不是对象；`api_version` 高于宿主当前版本；`panel_id` 与请求的面板不一致。
- `kind` 不在 26 种白名单内；`id` 缺失/重复/不合规；容器与叶子节点的 `children` 用法不符。
- 专属字段出现在不支持该 `kind` 的节点上（例如 `button` 带 `columns`）——**歧义即拒绝**，不静默忽略。

**业务级（Rust `control_validate`，`plugin.validateControl` 命令返回 `{ errors, warnings }`）**：

> **落地状态（2026-09）**：命令**已实现**——`apps/desktop/src-tauri/src/commands/plugin.rs` 的
> `plugin_validate_control`，直接复用 `crates/hp-core/src/control.rs` 的
> `ControlSchema::validate`（**不另写一份口径**）；面板归属与声明表由
> `hp_plugin_host::PluginHost::find_panel_owner` 反查注册表得到（不靠 `panel_id` 字符串切分）。
> JSON 不可解析时以 `errors` 返回而不是命令级失败，故前端拿到的永远是同一形状的判定结果。
> 命令形状遵循 D76（`{ ok, data?, error? }`）。

- 硬错误（拒绝）：上述全部解析层问题的服务端复算；`text_key` 缺失但 `text` 也缺失（必须有其一）；`bind.name` 未在 manifest 声明；`on` 的事件名不在谓词表、事件 id 未声明；`table.columns` 超过 8 列；`gap`/`align`/`variant`/`fit` 等枚举外取值；数值字段超出 `min`/`max`。
- 软告警（不阻塞，可渲染）：`visible_when` 的查询名当前无数据；`select` 的 `options_kind = bound` 但绑定为空 → 渲染为空态；节点数超过建议上限（64）时提示。

**宿主拒绝规则补充**：schema 含白名单外 `kind` → 不渲染该节点，渲染为 `empty('error')` 并广播一次 `plugin.error`；插件试图指定任意坐标/样式/文字 → 忽略并记录。

### 8. 渲染骨架（宿主侧）

- 落点：`apps/desktop/src/app_ui/shared/control/`（**受控渲染**；按职责分文件：`ControlPanelView` 面板级入口 / `ControlNodeView` 单节点与错误边界 / `ControlRenderer` 的 `kind → 组件` 映射 / `controlRenderCoverage` 覆盖清单 / `controlTokens` 外观映射 / `controlData` 数据快照与谓词 / `controlTypes` 宿主上下文）。
- 渲染器是**纯函数式**的：输入 `(schema 子树, 数据快照, i18n t, 事件回调)`，输出 React 元素；不读全局状态、不直连命令（事件回调由宿主注入）。
- **渲染缺口不可静默**：`CONTROL_RENDER_MAP` 是 `Record<ControlKind, …>`（缺一种即类型错误），另有 `controlRenderCoverage.ts` 覆盖清单供 `pnpm check:controls` 断言，新增 `kind` 必须同时补渲染实现。
- **接线状态（2026-09 更新：已接线）**：面板级入口 `ControlPanelView` 已接进
  `apps/desktop/src/app_ui/panels/PluginPanelHost.tsx`。装载链是
  「`api.pluginPanelSchema`（运行时通道）→ `api.pluginValidateControl`（业务级复算）→
  `ControlPanelView`（解析层校验 + 渲染）」，两道闸门的结论在
  `ControlPanelView` 内**合并**（任一道报硬错误即渲染错误态）；回调改在 `useEffect` 里触发，
  避免宿主在 render 阶段 `setState`。命令失败时该面板显示错误态，文案按结构化 `code`
  走 i18n（D27），`HpError.message` 只进诊断日志。
  **余留**：`bind` 的取数通道（插件 `data_queries`）与插件语言资源（`text_key` 取值）
  仍未落地，故当前传空数据快照、`tKey` 原样返回键名——绑定为空按本规范就是
  "渲染空态 + 软告警"，不伪造数据；事件回传链见第 6 节（**2026-09 已落地**）。
  这些防御由 `pnpm check:controls` 的运行时通道/接线断言守住（见「验证」）。
- 尺寸与外观**只取 token**（`gap`/`variant`/`fit`/`align` 映射到 `SPACE`/`RADIUS`/`FONT_SIZE` 与主题色），不写死像素、不引入自定义配色；浅色/深色由主题自动适配。
- 每个节点包一层错误边界：单个节点渲染失败只降级该节点为 `empty('error')`，不影响同面板其余节点。
- 浮层（`overlay`）里的面板同样用本渲染器；浮层**容器**的圆角/阴影/标签隐藏由蓝图节点声明、渲染时取同一套 token（D50），两者不重复定义外观。**（2026-09 已落地）**：容器渲染在宿主侧 `apps/desktop/src/app_ui/shared/overlayChrome.ts`——档位 → 像素/阴影取 `packages/ui` 的 `RADIUS`/`SHADOW`（不写死像素），叠放用 dockview 浮动窗口的 `--dv-overlay-z-index`；本渲染器不为容器定义任何外观。

## 与界面/多页面的关系

- 控件挂在**面板**之下，面板属于某个**界面（页面）**；界面切换 = **界面跳转**（蓝图行为），控件不参与跳转决策。
- 插件若需要"点了我的控件就换页面"，正确做法是**触发事件**，由蓝图规则决定是否产生界面跳转动作——与显示/隐藏同一条链路，宿主保持决策权。
- 浮层的显隐由蓝图的 **`overlay`（浮层）** 节点承载（D50）：浮层的**内容**（哪些面板/标签组）与**定位/尺寸/外观档位**都由蓝图声明，**是否显示由蓝图规则决定**，插件不能直接显隐浮层。
- 第一版：界面跳转的**运行时**（页面路由与切换）与蓝图求值接线一并落地，见 RFC 0007 相关里程碑；控件标准本身不定义路由。

## 明确不做（第一版）

- 插件自定义 React 组件、自定义 CSS、自定义配色。
- 浮层的任意层级、跨窗口叠加（定位只允许蓝图声明的九宫格锚点 + 双模式偏移 + 贴边收拢）。
- 插件声明浮层定位/尺寸（这些归蓝图）。
- 浮层进入 `panel_layouts` 布局持久化。
- 浮层跨界面或跨窗口叠加（挂载按界面隔离）。
- 浮层作为模态确认框使用。
- 插件直接触发界面跳转（只能触发事件，由蓝图规则决定）。

## 开放点（实现期）

- 浮层内控件的具体内缩/对齐档位枚举（定位本身已定为**九宫格锚点 + 双模式偏移 + 贴边收拢**）。
- 浮层是否允许半透明以外的背景处理（如毛玻璃）与是否跟随滚动。
- 同一界面浮层数量上限值。
- 浮层与布局块同为界面子级，其**显隐/定位/尺寸/外观档位由蓝图的 `overlay`（浮层）节点显式承载**（RFC 0007 / D50，**模型、校验、编辑器、蓝图侧运行时显隐与容器渲染均已实现**：含初始显隐对账、套用布局后重显、断开连接即收起；容器渲染落点 `apps/desktop/src/app_ui/shared/overlayChrome.ts`）。
- schema 的版本化方式（与宿主 API 版本的关系）：**已定**——`api_version` 随宿主 API 版本走（见下文「控件 schema 规范」第 1 节），本版固定为 `1`。
- 界面（页面）的入口如何选择：首个界面、显式标记的首页，还是仓库存一条当前页面状态（多页面落地时定）。
