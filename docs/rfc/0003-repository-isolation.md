# RFC 0003：仓库隔离与 SQLite 边界

状态：正式草案。已确认方向：全局配置库 + 每仓库一个 SQLite 文件，跨仓库不默认共享 tag/评分。

## 背景

文档要求“数据库以仓库为单位进行顶层分表”：仓库 A、仓库 B 可链接同一个本地媒体源，但两个仓库对该媒体源内图像的 tag、评分不互通。用户确认实现为每仓库一个 SQLite 文件。

## 决策

1. 应用存在一个全局配置库，保存应用级设置、仓库注册表、窗口/面板布局、插件全局开关。
2. 每个仓库一个独立 SQLite 文件，保存该仓库的媒体源挂载、文件索引引用、tag、评分、相册、同步规则。
3. 跨仓库查询默认禁止；如未来需要跨仓库搜索，必须通过显式只读聚合服务，不直接跨库 JOIN。
4. 同一个本地媒体源可被多个仓库挂载；真实文件不是仓库私有，仓库私有的是对该文件的解释数据。
5. 仓库库文件必须可备份、可迁移、可单独重建索引。

## 库职责

### 全局配置库

保存：

- 仓库注册表：仓库 ID、名称、仓库库路径、创建时间、最后打开时间。
- 应用设置：主题、语言、默认扫描并发、缩略图缓存位置。
- 面板布局：布局 JSON、当前工作区、最近会话；布局表放全局配置库，但每行带 `repo_id`，按仓库读取和覆盖。
- 插件注册表：插件 ID、版本、启用状态、权限授予状态。
- AI 提供方配置：只保存配置引用，不保存密钥明文；密钥存储方式属于实现期开放点，不影响仓库隔离边界。

不保存：

- 某张图片在某个仓库里的 tag。
- 某张图片在某个仓库里的评分。
- 某个仓库的虚拟相册成员。

### 仓库库

保存：

- 仓库元信息：仓库 ID、名称、schema 版本。
- 媒体源挂载：本地路径、别名、嵌套关系、挂载状态。
- 文件索引：稳定文件 ID、相对路径、哈希、状态。
- 仓库解释数据：tag、评分、色彩参考、AI 打标结果。
- 相册：`album`、`album_member`、`album_sync_rule`、`album_sync_state`。
- 操作历史：源间复制/剪切/移动、索引重建、同步记录。

## 一致性规则

> **后续修订（用户确认）**：下一行的"卸载媒体源时保留文件索引，标记源离线"**已被取代**。
> 界面上的「卸载」现为**完全卸载**：在一个事务里删除该源的 `files`、`file_tags`/`file_auto_tags`、
> `ratings`、`color_refs`、`album_member`、`ai_tag_undo`，以及引用该源的 `album_sync_rule`/`album_sync_state`
> （对应跟随相册降级为 `fixed`），子源摘挂为顶层源，最后删除 `sources` 行；**磁盘上的真实文件不动**。
> 取消会整体回滚。底层"标记离线"（`RepoDb::unmount_source`）保留给**历史离线行**与恢复场景，
> 相关读取过滤（`list_mounted_sources` / `file.query` / 相册可见成员 / 同步空操作）继续作为兜底。
> 细节见 `docs/spec/commands-events.md` 第 3.2 节。

- 全局库知道“有哪些仓库”，仓库库知道“这个仓库如何解释文件”。
- 删除仓库时默认只删除仓库注册与仓库库，不删除真实媒体源文件。
- 卸载媒体源时保留文件索引，标记源离线；重新挂载同一路径且内容哈希一致时恢复解释数据。（**已被上方修订取代**）
- 仓库库损坏时允许从媒体源重建文件索引，但 tag、评分、相册不可自动重建；必须提示备份/导出策略。

## 风险

- 多仓库同时挂载同一媒体源会增加 watcher 与扫描去重复杂度。
- 每仓库一个文件会让全局搜索变弱；需要明确首期是否不做跨仓库搜索。
- 面板布局表在全局配置库但按 `repo_id` 隔离；实现时必须保证所有布局查询都携带当前仓库上下文。

## 实现期开放点（非架构决策）

- 仓库库文件命名与默认存放位置。
- 密钥/AI token 使用 Windows Credential Manager 还是其他安全存储。
- 仓库导出格式是否包含 SQLite 原文件 + JSON 清单。
