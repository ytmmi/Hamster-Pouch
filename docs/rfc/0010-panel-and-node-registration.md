# RFC 0010：面板与蓝图节点注册（插件可注册面板与蓝图节点）

状态：正式草案。本文记录用户 2026-09 一次性确认的四项改动，并把「**谁可以注册什么**」固化为三张注册表的契约：

1. **插件可以注册面板与蓝图节点**（明确：**插件不可以注册控件**）。
2. **面板注册与声明参数列表标准化**（新版 `docs/spec/panel-standard.md`）。
3. **蓝图节点类型与声明列表标准化**（修订 `docs/spec/blueprint-node-standard.md`）。
4. **「全部设置」系统界面**（新版 `docs/spec/settings-standard.md`）。

同时执行两项**仅显示用语**的术语改名（本文决策 1）。本文不改变任何 JSON 字段名与枚举取值；实现不得反向修改这些决策，除非用户明确要求重开。

## 已确认决策

### 决策 1：术语改名（仅显示用语，JSON 不变）

| 原显示名 | 新显示名 | 枚举值 | 字段 / 库表 / 命令 |
| --- | --- | --- | --- |
| **面板控件**（Panel Control） | **面板**（Panel） | `control`（不变） | `panel_id` 等全部不变 |
| **类**（Class） | **类目**（Category） | `class`（不变） | `control` / `media_type` 等全部不变 |

改名理由：新版把「**面板**」确立为**可注册对象**（决策 2），「控件」则**专指面板内部的 26 种宿主标准 UI 单元**；两者必须各占一个词。D46 当年把「控件」改称「面板控件」正是为了躲开后者，现在退回「面板」，同名冲突彻底消失。

口径与 D46 / D68 一致：**只改文档与 UI 显示用语**，`packages/config` 的枚举、i18n 键名、`panel_layouts` 表、命令名一律不动。历史决策条目（D28/D44/D46/D49/D50/D56）**保持原文**，其措辞由 `docs/architecture/decision-checklist.md` 的修订说明统一承接，不逐条改写。

**「浮动控件」不受本决策影响**：它是 2026-09 已取消的概念，在所有文档中作为历史记录**原样保留**。

改名的**直接后果**（必须同步，否则文档自相矛盾）：

- 蓝图结构层级改写为 **界面 ⊃ 布局块 ⊃ 标签组 ⊃ 面板 ⊃ 类目 ⊃ 对象**；浮层与布局块同级，内容为面板/标签组。
- D46 的「面板控件」与 D104 的「同名不同义的「控件」已消除」两条口径改由本决策承接。
- 「全部设置」的对应大类叫**「面板」**，不叫「控件」（决策 7）。

### 决策 2：插件可以注册**面板**与**蓝图节点**，不可以注册**控件**

| 注册对象 | 宿主 | 插件 | 依据 |
| --- | --- | --- | --- |
| **控件**（面板内部的标准 UI 单元） | 内置 26 种 | ❌ **不能注册** | D62 不变：`kind` 是宿主内置白名单，插件不得新增 |
| **面板**（仓库 / 查看器 / 插件提供的功能面板） | 内置 13 个 | ✅ **可注册** | 本文决策 4 |
| **蓝图节点类型** | 内置 10 种 | ✅ **可注册** | 本文决策 5、6 |

边界（不因本决策放松）：

- 插件仍然**不得**创建自由 React 组件、自定义 CSS / 配色、独立窗口（RFC 0004 决策 12 / D44）。
- 插件注册的**面板**只能声明「要一个什么样的面板」；面板内部的 UI 仍由控件 schema 与宿主白名单决定（`docs/spec/control-standard.md`）。
- 插件注册的**蓝图节点类型**是**纯声明**的（决策 6），不含代码。
- 插件注册**不构成权限**：注册 ≠ 可用，实际可用性仍由「插件是否在该仓库启用 + 该能力是否授权」决定（RFC 0004 决策 6/14）。

### 决策 3：注册是**声明式**的，宿主是唯一的执行者

三张注册表统一遵循：

1. **声明与执行分离**：插件只提交声明（纯数据），宿主负责解析、校验、映射到受信实现。
2. **注册项不落用户数据**：注册表随插件包存在，**不写入任何库表**；卸载插件即注册项消失（决策 6 定义此时的行为）。
3. **宿主是最终裁决者**：白名单外的取值一律拒绝；插件的声明永远不能绕过宿主校验。
4. **稳定 ID 与命名空间**（见「命名空间」一节）：注册项 id 全局唯一，跨插件冲突由命名空间规则消解，不靠"先到先得"。

### 决策 4：面板注册表与声明参数列表标准化

插件通过 manifest 贡献点 `panel` 注册面板（字段扩展见 `docs/spec/plugin-standard.md` 第 4 节），宿主持有一份**面板注册表**（`docs/spec/panel-standard.md`）。每个面板必须声明：

| 声明参数 | 必需 | 用途 |
| --- | --- | --- |
| `id` | ✅ | 面板稳定 id；蓝图 `panel_id` 引用它 |
| `title_key` | ✅ | i18n 键（D27），面板标题与「全部设置」条目名 |
| `category` | ✅ | 面板分类，供「全部设置 → 面板」二级列表分组 |
| `has_class` | ✅ | **有无类目**：该面板能否挂「类目」节点 |
| `blueprint_node` | ✅ | 该面板在蓝图里由哪种节点承载（缺省 `control`） |
| `settings` | — | 面板自身设置项声明，供「全部设置 → 面板」分节渲染 |
| `capabilities` | — | 该面板需要的能力；建面板与写操作按仓库校验 |
| `mount` | — | 宿主约束：可挂载位置（可作浮层内容、可浮动、可否被蓝图引用） |
| `read_only` | — | 缺省 `true`；`false` 需 `repo.write` |
| `icon` / `default_size` | — | 显示层信息（同 D65） |

`has_class` 是本版新增的核心参数：它是「面板」与「类目」之间的唯一开关，取代此前"任何面板都可能有类目"的隐含假设。其违约口径按**声明者是否可变**区分：

- **宿主内置面板**（13 个）：`has_class` 固定，`panel → class` 边为**硬错误**（宿主声明是不变量）。
- **插件注册面板**：`has_class` 随插件版本可变，违约按**未接通软告警**——灰显、**允许保存**、插件恢复后自动恢复（与决策 6 同口径）。否则插件一次升级就能把用户既有文档变成"保存失败"。

### 决策 5：蓝图节点类型注册表标准化

10 种内置节点类型的定义表（D64）升级为**注册表**，并开放给插件（`docs/spec/blueprint-node-standard.md`）。每个节点类型声明：

| 声明参数 | 说明 |
| --- | --- |
| `type` / `label` / `role` / `nameFromLayer` / `providesName` / `fields` / `parents` / `children` / `events` | **保留现有定义表全部字段**（D64 向后兼容） |
| `ports` | 端口与允许的边类型（此前由 `role` + `parents`/`children` 推导，现允许**显式声明**） |
| `severity` | 校验策略：该类型的字段/引用问题算**硬错误**还是**软告警（未接通）** |
| `evaluation_role` | 引擎语义：是否进结构树、是否为规则节点、是否可做动作目标 |
| `origin` | 来源与启用状态：宿主内置，或哪个插件注册 |

推导与显式声明并存：`ports` 未声明时按现有规则**由定义表推导**（保持现有 10 种的行为完全不变）；显式声明只对需要它的类型生效。

### 决策 6：插件注册的蓝图节点是**纯声明式 + 受控校验规则**

插件注册的节点类型**不得**携带代码、自定义渲染、自定义画布外观或任意表达式。允许声明的内容：

- 角色与字段（从宿主预定义的角色与字段类型里选）；
- 端口与边类型（从宿主既有的 `contains` / `memberOf` / `on` / `fires` / `guards` 里选）；
- **受控校验规则**：从宿主提供的**固定最小集**里选（同 `condition.expr` 的口径，D32——不接受任意表达式）；
- `severity`（硬错误 / 软告警）；
- `evaluation_role`（引擎按角色统一执行，插件不能定义执行逻辑）。

**插件缺失时的行为**：插件被卸载、未安装、未在该仓库启用，或宿主 API 版本不兼容时，蓝图里由它声明的节点类型按**未接通**处理：

1. **软告警**，不阻塞保存（**不是**硬错误）；
2. 画布**灰显**并标注「未接通」，与 D55 软删除的既有机制同款；
3. 节点与边**原样保留**在文档里，不参与求值、不参与结构对账；
4. 插件重新可用后**自动恢复**，不需要用户重连或重建节点。

这条**替换**了"未知 `type` 一律硬错误"的既有口径：未知类型现在区分两种——**语法非法**（非 `type` 命名规则）仍是硬错误；**命名合法但当前无对应注册项**（插件缺失）按未接通软告警处理。理由：否则用户装过插件再卸载，他自己的蓝图会**直接保存失败**，等于数据被插件绑架。

### 决策 7：「全部设置」是应用级系统界面

新增**系统界面**概念（`docs/spec/settings-standard.md`）：

- **入口**：顶部设置 → 「更多设置」，跳转到名为「全部设置」的界面。
- **性质**：**系统界面，用户不可自定义**；**应用级**，独立于仓库蓝图——**不进 `blueprints` 表、不受蓝图引擎管辖**，跨仓库共享同一份。
- **结构**：顶部搜索框 + 左右分栏。左为大类（可含二级列表），右为详细设置（可用横线分节）。
- **大类**：界面 / 蓝图 / **面板** / 插件 / 语言。
  - **面板**：管理各面板设置，**按面板分节**；二级列表按面板 `category` 列出各面板。
  - **插件**：二级列表按插件分类列出各插件。
- **插件可增加设置**：经新贡献点 `settingsSection` 声明（`docs/spec/plugin-standard.md`）。
- **搜索**：跨全部大类与二级项检索设置项，命中即跳转定位。

## 命名空间

注册项 id 必须全局唯一，且**不能**出现"插件注册一个叫 `media` 的面板把宿主面板顶掉"这类情况：

| 注册对象 | 宿主内置 id | 插件注册 id |
| --- | --- | --- |
| 面板 | 裸 id（`repo` / `media` / `viewer` …） | **必须** `plugin.<plugin_id>.<local_id>` |
| 蓝图节点类型 | 裸 `type`（`interface` / `control` / `class` …） | **必须** `plugin.<plugin_id>.<local_id>` |
| 控件 `kind` | 裸 `kind`（`row` / `text` …） | —（插件不可注册） |

- `plugin_id` 即 manifest 的 `id`（`^[a-z0-9][a-z0-9._-]{2,63}$`）。
- 宿主的蓝图 `panel_id` 与节点 `type` 因此天然不会与插件注册项冲突，**不需要**"加前缀消歧"的运行时猜测。
- 该形式与既有插件命令命名空间 `plugin.{pluginId}.{action}` 同源。

## 明确不做（第一版）

- 插件注册**控件**（26 种 `kind` 仍是宿主内置白名单，D62 不变）。
- 插件注册带**自定义渲染 / 自定义校验表达式 / 自定义引擎逻辑**的蓝图节点（决策 6 的边界）。
- 插件覆盖或替换**宿主内置**面板与节点类型（命名空间上不可能，且不提供覆盖机制）。
- 注册项写入用户数据库（注册表随插件包存在，不落库）。
- 用户自定义「全部设置」界面（它是系统界面）。

## 开放点（实现期）

- 面板 `category` 的完整取值域（本版给最小集，实现时按真实面板补齐并同步"全部设置"二级列表）。
- `ports` 显式声明与推导并存时，冲突（声明与推导不一致）该报硬错误还是以声明为准。
- 插件注册节点类型的**上限**（单插件与全局各一个建议上限，防注册表爆炸）。
- 插件注册的节点类型能否参与**结构边**（作为 `contains` 的父/子），还是仅允许规则类（`event`/`condition`/`action` 位置）。
- 「全部设置」搜索的匹配口径（仅 `title_key` 文案，还是含关键词与同义词）。
- 插件注册节点类型的**画布外观**（图标/配色档位）是宿主按 `role` 统一给，还是允许声明 token 档位。
