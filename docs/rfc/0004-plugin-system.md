# RFC 0004：插件系统顶层决策

状态：正式草案。本文记录用户已确认的插件系统方向；实现期开放点不得反向修改这些决策。

## 已确认决策

1. 插件统一建模为“插件包 + 信任等级”。
2. 本地开发插件视为 git 插件的本地路径形式，不单独建一套插件类型。
3. 插件运行形态由插件在 manifest 中自声明；宿主负责校验运行形态、能力、信任等级是否匹配。
4. 权限模型采用能力制，并对高危能力做显式标记。
5. git 插件安装采用锁定版本 + 手动更新。
6. 插件采用“全局安装 + 按仓库启用 + 按仓库能力授权”：启用只决定插件是否可用于该仓库，高危读写能力仍需在该仓库单独授权。
7. 已确认的插件形态示例：AI 打标默认外部进程；3D 模型预览等性能敏感能力可声明动态库。
8. 信任等级枚举为 `system` / `trusted` / `community` / `local-dev`。
9. 首期支持 WASM 插件形态。
10. 动态库崩溃隔离按信任等级区分；`system`/`trusted` 可使用动态库，`community`/`local-dev` 不允许使用动态库。
11. git 插件签名校验首期不强制，锁定 commit/tag 即可；每次更新保留旧插件包目录，回滚即切回旧目录。
12. 插件 UI 面板采用受控组件/schema 渲染；插件不直接渲染自由 React 组件。
13. WASM 插件首期必须有资源限额、按仓库授权、纯数据输出；在最小输入输出基础上增加受控查询。
14. 只读面板能力随仓库启用默认授予；读写和高危能力仍需按仓库授权。
15. 插件宿主 API 显式版本化。
16. AI 打标结果直接写入，但必须标记来源、置信度和生成时间；高置信结果可覆盖用户已有 tag，且必须保留撤销记录。
17. 插件来源由宿主按实际安装方式判定，manifest 不得自称 `system`。
18. `system` 权限必须签名，且只能由主线仓库构建人员签发（当前仅 `ytmmi`）。
19. 二进制分发包格式为 `.zip`。
20. WASM 运行时选型为 `wasmi`。
21. `external-process` 插件允许自带原生依赖（DLL、模型权重等）。
22. 插件可创建控件（~~含浮动控件~~ **2026-09 修订：浮动控件类别已取消**，浮层由蓝图 `overlay` 容器承载、内容为面板），前提是先规范仓库控件标准（`docs/spec/control-standard.md`）。
23. 增加「Python 核心」system 插件待办：为插件提供 Python 环境，使 Python 插件可以源码分发。
24. Rust 插件不使用源码分发（要求用户侧编译不可接受），必须走二进制包。

## 插件包模型草案

```text
plugin-package/
  plugin.manifest            # 清单：ID、版本、入口、运行形态、能力、贡献点
  bin/ 或 lib/               # 外部进程可执行文件，或动态库
  assets/                    # 图标、面板资源、说明
  README.md
  LOCK                       # git 安装时记录 URL + commit/tag + 获取时间
```

`plugin.manifest` 至少包含：

- `id`：全局唯一插件 ID。
- `name` / `version` / `min_host_version`。
- `source.kind`：**不由 manifest 声明**；来源是宿主按实际安装方式判定的事实（`system` / `git` / `local-path` / 归档包），写入注册表。
- `runtime.kind`：`external-process` / `dynamic-library` / `wasm`。
- `entry`：进程入口或动态库入口。
- `capabilities`：能力列表，例如 `ui.panel`、`repo.read`、`repo.write`、`fs.read`、`fs.write`、`network`、`ai.infer`、`native.code`。
- `high_risk`：高危能力标记；`native.code`、`fs.write`、`network` 默认高危。
- `contributions`：面板、命令、查看器、AI 提供方、元数据字段。**标准化后为类型化的贡献点对象**（`{ kind, id, title_key, read_only, media_type, returns, model_kind }`），旧的字符串数组（`["panel"]`）由解析层兼容；完整契约见 `docs/spec/plugin-standard.md`（D65）。
- `api_version`：插件实现的宿主 API 版本（与 `min_host_version` 一起构成兼容区间）。
- `data_queries` / `events`：控件数据绑定与事件回传的声明清单（控件标准第 5/6 节）。
- `native_dependencies`：原生依赖（DLL / 模型权重），缺失即拒绝加载（D43）。
- `trust.requested`：插件请求的信任等级；枚举为 `system` / `trusted` / `community` / `local-dev`。

## 信任与安装

- 系统插件：随应用发布，更新跟随应用版本；仍必须声明能力，不允许隐式全权。
- 系统插件由安装包内的清单在安装期登记，不由用户投放到插件目录后被 `discover` 认领为系统插件。
- git 插件：安装时记录 git URL 与锁定 ref；默认锁定 commit 或 tag。
- 更新：不自动更新；用户手动检查并确认更新；更新时保留旧插件包目录，失败或用户回滚时切回旧目录。
- 本地路径插件：按 git 插件的本地路径形式处理，默认信任等级为 `local-dev`。
- 普通 git 插件默认信任等级为 `community`；用户可显式提升为 `trusted`，提升操作必须记录。
- 签名/校验：git 插件的签名校验首期不强制（沿用决策 11）；**`system` 等级例外，必须签名**（见下）。
- 来源与信任分离：manifest 的 `source.kind` 不参与信任判定；`effective_trust` 只接受宿主判定出的来源。

## system 等级签名要求

- `system` 是唯一能解锁动态库（D4）与后续高权限能力的等级，因此**不以 manifest 自称为依据**。
- 签名主体：**主线仓库构建人员**，当前仅 `ytmmi`；公钥随应用内置，私钥不得进入仓库与构建产物。
- 校验时机：安装时校验，加载时复核；校验使用随应用内置公钥的**公钥指纹白名单**，指纹变更必须随应用版本发布。
- 签名覆盖范围：插件包内 `plugin.manifest` 与全部被加载的文件（`entry`、动态库、Python 入口、原生依赖）。
- 校验失败的处理：拒绝安装或降级为 `community` 并要求用户显式确认，**不得静默提升**。
- 任何信任等级提升都必须写入事件与操作记录（沿用「提升操作必须记录」）。

## 分发通道

| 通道 | 形态 | 适用 | 备注 |
| --- | --- | --- | --- |
| 应用安装包 | 源码随仓库 + 安装期登记 | 系统插件、Python 核心 | 更新跟随应用版本 |
| git | 锁定 commit/tag | 源码可达的插件（含 Python 插件） | 手动更新 + 目录切换回滚 |
| 归档包 | **`.zip`** | Rust 插件、含原生依赖的插件 | 必须带摘要文件；`system` 需签名 |
| 本地路径 | 目录 | 开发调试 | 默认 `local-dev` |

- **Rust 插件不使用源码分发**：用户侧编译不可接受，一律走二进制包（决策 24）。
- **Python 插件可以源码分发**：由「Python 核心」system 插件提供 Python 环境（决策 23）。
- `.zip` 解包必须防御绝对路径、`..` 段、符号链接逃逸，并限制解压后总大小与文件数。
- 摘要文件（哈希清单）**与包分离发布**才有安全意义；同一页面上的哈希只防传输损坏。

## 运行形态边界

- `external-process`：默认隔离形态；适合 AI 打标、网络服务、不可信或不稳定插件；**允许自带原生依赖**（DLL、模型权重等），原生依赖必须列在 manifest 中并随包一同校验。
- `wasm`：首期支持，运行时为 **`wasmi`**；适合低风险 UI 辅助、纯计算、格式转换；必须有资源限额（内存上限、fuel/指令数、墙钟超时、输出字节上限），按仓库授权，且只能输出可序列化数据。
- `dynamic-library`：性能敏感插件可声明；必须标记 `native.code` 高危能力；仅 `system`/`trusted` 插件允许加载动态库。
- 宿主校验规则：
  - 插件声明 `dynamic-library` 但未声明 `native.code`：拒绝加载。
  - 插件声明 `dynamic-library` 但信任等级不是 `system`/`trusted`：拒绝加载。
  - 插件请求高危能力但信任等级不足或当前仓库未授权：拒绝加载或要求用户显式升级授权。
  - 插件声明能力但实际调用越权 API：宿主拒绝并记录事件。
- 动态库崩溃隔离按信任等级区分：`system`/`trusted` 可允许 in-proc；`community`/`local-dev` 不允许加载动态库。
- 系统/受信动态库 ABI 使用 C ABI + 版本化结构体；结构体版本不兼容时拒绝加载。

## 仓库作用域

- 插件安装是应用级行为；插件启用与能力授权是仓库级行为。
- 仓库关闭插件后，该插件不得读取该仓库数据、不得注册该仓库面板、不得接收该仓库事件。
- 插件写入数据必须携带仓库上下文，宿主校验该插件在当前仓库已启用且已获得对应能力授权。
- `repo.read`、`repo.write`、`fs.write`、`network`、`ai.infer` 等能力需要按仓库单独授权；只读面板能力随仓库启用默认授予。

## 面板与 UI 贡献

- 插件可贡献面板，但面板布局状态仍按仓库持久化到配置库表。
- 插件面板只能通过受控组件/schema 渲染；宿主负责把 schema 映射到受信任的 React 组件集合。
- 插件可创建**控件**，控件标准先于实现落地（`docs/spec/control-standard.md`）；插件不得创建自由 React 组件、不得创建独立窗口。
- ~~**浮动控件**是控件的一种：与**布局块同级**（同为界面直接子级），**显示高度在布局块之上**（整体浮层覆盖）；可定义圆角、阴影、标签隐藏等外观；**不是独立窗口**（D49）。~~ → **已取消（2026-09）**：浮层改由蓝图 **`overlay` 容器**承载（内容为面板，定位/尺寸/外观档位由蓝图声明），见 D50 修订。
- 插件命令必须进入统一命令体系，不允许绕过 Tauri 桥接层直接调用核心 crate。
- 插件宿主 API 显式版本化；插件声明兼容的 host API 版本，破坏性变更必须升大版本。

## Python 核心（待办）

- 目标：以 system 插件形态提供 Python 运行环境，使 **Python 插件可以源码分发**（策略见 RFC 0009）。
- 职责：内嵌解释器或随包 Python 运行时的生命周期、虚拟环境与依赖安装、`external-process` 形态的入口拉起、按仓库的能力令牌下发、资源与超时监督。
- 约束：Python 插件默认 `external-process` 形态、默认 `community` 信任等级；不得绕过宿主 API 直接访问数据库或文件系统。
- 依赖获取在安装期由用户确认后获取，或随 Python 核心插件一并提供（**D20 只约束构建链本地化，不涉及运行期联网**；插件联网须按仓库授权 `network` 能力）。
- 交付形态为二进制包（决策 19），随应用安装包分发并按 `system` 等级签名（决策 18）。

## 风险

- 插件自声明运行形态会提高灵活性，但必须由宿主做强制校验，否则高危能力会被绕过。
- 来源若允许 manifest 自称，任何本地目录都能自封 `system` 并解锁动态库；来源必须由宿主判定（决策 17）。
- 动态库插件可能破坏进程稳定性；ABI 版本、崩溃隔离、超时策略必须在实现前定。
- git 插件供应链风险高；锁定版本只能保证可复现，不能保证恶意更新不存在。
- 二进制包在签名缺失时只是「可复现」而非「可信」；`.zip` 通道必须靠 `system` 签名（决策 18）与来源声明互补。
- Python 插件源码分发使可审计性回归，但也带来依赖获取与版本漂移风险，须由 Python 核心统一收敛。

## 实现注意

- `system`/`trusted` 动态库使用 C ABI + 版本化结构体；任何 ABI 变更必须同时升级插件包大版本和宿主校验版本。
- `community`/`local-dev` 插件只能使用 `external-process` 或 `wasm`。
- WASM 宿主函数允许受控查询，但不允许直接操作 UI、数据库或文件系统。
- WASM 运行时为 `wasmi`；宿主导入函数的名称、签名、内存归属与序列化格式必须先于实现定义。
- `external-process` 插件的 `entry` 必须相对版本目录解析，禁止 manifest 指定任意命令；原生依赖随包校验，缺失即拒绝加载。
- 外部进程插件需要监督规则：崩溃重启次数与退避、连续失败 N 次后标记不健康并广播 `plugin.error`。
- git 插件更新必须保留旧插件包目录；回滚是目录切换，不重新依赖网络。
- 插件存储根目录不使用 Windows Roaming 目录（插件与原生依赖可能数百 MB）。
- 签名私钥不得进入仓库、CI 日志与构建产物；公钥指纹白名单随应用版本发布。
