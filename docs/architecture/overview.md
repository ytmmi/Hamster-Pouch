# 仓鼠颊架构总览

状态：正式草案。本文合并已确认决策，作为 AI 编码协作者的入口文档。实现时可以补充细节，但不得反向修改 `docs/architecture/decision-checklist.md` 与 `docs/rfc/*.md` 中的已确认决策。

## 1. 产品与技术约束

- 仓鼠颊是 Windows 本地资源管理软件；第一阶段围绕图像 + 视频管理（音频仅写占位行，未知类型不索引，见 D11）。
- 技术栈：Tauri + React + TypeScript。
- Rust 侧使用 Cargo workspace 多 crate；前端使用 pnpm workspace。
- `packages/shared-types` 由 Rust 类型生成。
- 代码文件规则：单文件不超过 1200 行、职责单一、按功能分类、禁止用内部嵌套规避拆分。
- 依赖与构建链本地化（D20）：凡能部署在项目内的一律项目内化；无法项目内化的必须告知用户。

## 2. 核心概念

- 仓库（Repository）：解释数据的隔离边界。每个仓库一个 SQLite 文件。
- 媒体源（Source）：真实本地文件夹，可嵌套，可挂载到仓库。添加时**经原生文件夹对话框选取目录**，源名称**默认取所选文件夹名**；别名只能在**添加之后**修改（添加时不填别名）。
- 文件（File）：由内容哈希识别身份；路径、size、mtime 只是定位与变更触发；含媒体类型 `media_type`（image/video/audio）。
- 虚拟相册（Album）：成员关系容器；固定型只维护成员，跟随源型额外维护同步规则；含媒体属性 `media_type`，只显示属性包含类型的文件。
- tag / 评分 / 色彩参考 / AI 结果：仓库内解释数据，跨仓库不共享。
- tag 关系：tag 之间的层级与关联（多父级 DAG），作为关系图谱组件的数据源（D22）；tag 实体、关联与关系均按仓库独立（D23）。
- tag 库（四库）：应用级共享的 tag 参考体系（RFC 0008 / D33-D37），由**库 1 概念总库**（一条记录 = 一个 tag 概念，持稳定 ID）为基底，上叠**库 2 关系映射**（默认关系 + 扩展关系，规则同 tag 表控件）、**库 3 分类映射**（艺术家/原作/角色 + 专属字段，同名角色靠 IP 识别）、**库 4 别名与多语言**（每语言一个标准名，其余为别名）；全部以库 1 `tag_id` 为外键。**完整数据不随应用分发**（D36）：应用只内置轻量基底库，完整词库（含全量 artist）为按需安装的扩展包，用户自定义落独立可写用户库，查询经聚合层统一。**扩展包与插件系统的衔接方式延后到构建时讨论**（D36.1）。
- tag 词库：应用级共享的多语言参考词表（主中文、辅日语/英语），独立于仓库 tag（RFC 0006）；任意语言命中后按中文聚合，服务于 AI 打标归一化、打标输入建议、跨语言检索与 tag 表展示映射。RFC 0008 确认后由 tag 库承接，其实体锚点决策被 D33 取代。
- 人工 tag 与自动 tag：tag 实体共用，关联使用独立表，同名可共存；展示上人工组在上、自动组在下（自动可折叠）（D21）。
- tag表组件：以层级树呈现 tag；交叉关联以同名为关联点（多父级 tag 在每个上级下各出现一次并以浅蓝色标示）；支持右键新增同级/子标签、重命名，拖拽=移动（D24）。
- 面板（Panel）：React 受控组件；布局按仓库持久化到全局配置库，行内带 `repo_id`。面板最小尺寸只约束正文（6px），标签条始终保留可见（D25）。**面板是可注册对象**：宿主内置 15 个（含图书预览 `bookpreview`）+ **插件可注册**，声明参数（`category` / `has_class` 有无类目 / `blueprint_node` / `settings` / `capabilities` / `mount` / `origin`）见 `docs/spec/panel-standard.md`（RFC 0010 决策 2/4）。
- 蓝图（Blueprint）：仓库内节点式显隐与组布局配置（RFC 0007 / D28-D32 / D46-D60 / **RFC 0010**）；在 `layout.*` 的位置/大小/分组结构基准上叠加控制显隐、面板组收起（最小化 6px）、组拉伸、组位置（x/y）与隐藏方向；节点分**界面（层的根）/ 布局块 / 标签组 / 面板（旧称「面板控件」，RFC 0010 决策 1 退回「面板」）/ 类目（旧称「类」）/ 对象 / 浮层 / 事件 / 条件 / 动作**，**布局块 = 界面上的一个区域（栏）**。**注意两棵树**：蓝图**结构树**是 `面板 ⊃ 类目 ⊃ 对象`；**控件**（26 种标准 UI 单元）不是蓝图节点，只在**面板内部**渲染。**节点类型可注册**：宿主内置 10 种 + **插件可注册**（声明 `ports` / `severity` / `evaluation_role` / `origin`，纯声明式；插件缺失时按**未接通**软告警、**允许保存**、恢复后自动恢复），见 `docs/spec/blueprint-node-standard.md` 第 2.3、2.4 节。**分层**：一个层 = 一张画布 = 一个界面（页面），层名可自定义且蓝图内唯一；**每层一份面板布局**（D53），**当前层按仓库持久化**（D54）；**动作含界面跳转 `navigate`**（跨层），**浮层节点是容器**（直接 contains 面板/标签组，D50/D56）；**生效蓝图优先级**：布局绑定 → `is_default` → 内置默认（D58；常量回退在前端运行时，装载时补种为库存默认）。默认蓝图复现现状双击联动（当前 27 节点 / 26 边 / `default_version`=7）；模板应用级共享。保存后**热更新**到布局（跨窗口事件/令牌 + 轮询安全网），编辑器删除为软删除（关联节点保留、灰显未接通），右键划线**一次可删多个节点与连线**（批量、原子，2026-10 D86）；**新增节点只追加自身**（不连带补最小链、不自动挂钩，缺引用灰显未接通，2026-10 D84），画布**右下角有小地图**（缩略当前层节点/连线 + 视口指示框，拖动即定位，2026-10 D85）。**`hide_direction` 的"指定邻居吸收空间"运行时未实现**（模型 / 校验 / 编辑器已支持）。

## 3. 总体分层

```text
React 面板层
  apps/desktop/src + packages/ui
Tauri 桥接层
  apps/desktop/src-tauri：参数校验、权限检查、命令/事件桥接
Rust 核心层
  crates/hp-core、hp-store、hp-scanner、hp-hash、hp-album、hp-fsops、hp-plugin-host、hp-ai、hp-media、hp-book
数据/文件层
  全局配置库、仓库 SQLite、tag 词库 SQLite（RFC 0006）、媒体源真实文件、缓存/缩略图、插件包目录
```

依赖方向只允许向下：`UI -> Tauri -> crates -> 数据/文件`。禁止 UI 直连 SQLite，禁止插件直连数据库或文件系统。

## 4. 文件与身份

- 文件身份 = 内容哈希。
- 感知哈希只用于相似/重复检索，不参与身份合并。
- 文件变更监听 = watcher 实时监听 + 定期全量校验兜底。
- watcher 事件丢失、溢出或路径异常时，必须触发局部或全量重扫。
- 媒体源间复制/剪切/移动是真实文件操作；只要内容哈希一致，仓库内 tag、评分、相册成员关系不丢失。

## 5. 仓库隔离

- 全局配置库保存：仓库注册表、应用设置、面板布局表（含 `repo_id`）、插件注册表、AI 配置引用。
- 每个仓库一个 SQLite 文件，保存：媒体源挂载、文件索引、tag、评分、相册、同步规则、操作历史。
- 跨仓库默认不共享 tag/评分；跨仓库搜索不进入第一期。
- 同一媒体源可被多个仓库挂载；真实文件共享，解释数据隔离。

## 6. 虚拟相册

- 固定型：创建时写入 `album_member`，之后不自动跟随源变化。
- 跟随源型：保存 `album_sync_rule` + `album_sync_state`，并按规则维护 `album_member`。
- 媒体属性：`image` / `video` / `audio` / `multimedia`，默认 `multimedia`；相册只显示属性包含类型的文件；修改属性移除不匹配成员（UI 确认 + 写历史）；嵌套默认继承父相册、可覆盖（D10）。
- 跟随源同步规则含独立 `media_type` 过滤，属性变更联动更新（D13）。
- 同步模式：`add_only` 只增量加入；`mirror` 可移除非 pinned 成员。
- 用户手动加入跟随型相册的成员需要能与同步加入成员区分；pinned 语义见 `RFC 0002`。

## 7. 插件系统

- 插件统一为“插件包 + 信任等级”。
- 信任等级：`system` / `trusted` / `community` / `local-dev`。
- **来源由宿主判定，不由 manifest 自称**：`system`、`git`、`local-path`，另有归档包通道（`.zip`，见 RFC 0009）。
- `system` 等级必须持有**主线仓库构建者签名**（当前仅 `ytmmi`）；`trusted` 仍需用户显式提升并记录。
- 运行形态：`external-process` / `wasm` / `dynamic-library`。
- AI 打标默认外部进程；3D 模型预览等性能敏感能力可声明动态库。
- 动态库仅 `system`/`trusted` 可用，ABI 为 C ABI + 版本化结构体。
- WASM 运行时选 `wasmi`；必须有资源限额、按仓库授权、纯数据输出，并只允许受控查询宿主函数。
- 二进制分发包格式为 `.zip`；`external-process` 插件允许自带原生依赖（DLL / 模型权重）。
- **Rust 插件不走源码分发**（用户侧需编译，不可接受）；由 system 插件“Python 核心”提供内嵌 Python 环境，**Python 插件走源码分发**（待办）。
- git 插件：锁定 commit/tag，手动更新，保留旧插件包目录，回滚切回旧目录。
- 插件全局安装，按仓库启用；只读面板能力随启用默认授予，读写/高危能力按仓库授权。
- 插件 UI 只能是受控组件/schema，由宿主映射到受信任 React 组件；**注册权边界（RFC 0010 决策 2）**：插件**可以**注册**面板**（贡献点 `panel`）与**蓝图节点类型**（贡献点 `blueprintNode`），**不可以**注册**控件**（26 种 `kind` 是宿主内置白名单，D62 不变）——插件只能在**自己的面板内**按 schema **使用**控件。注册项命名空间统一为 `plugin.<plugin_id>.<local_id>`，**不落库**、随插件包存在；插件缺失时蓝图里的引用按**未接通**处理（软告警 + 灰显 + 允许保存 + 恢复后自动恢复）。**「浮动控件」类别已于 2026-09 取消**——"浮在布局之上的一层显示"由蓝图的 `overlay`（浮层）容器承载，内容就是面板。控件标准见 `docs/spec/control-standard.md`，面板标准见 `docs/spec/panel-standard.md`。
- **「全部设置」系统界面（RFC 0010 决策 7）**：应用级**系统界面，用户不可自定义**，**不进 `blueprints`、不受蓝图引擎管辖**；顶部设置「更多设置」进入，顶部搜索框 + 左右分栏（左大类/二级、右分节设置），大类为 **界面 / 蓝图 / 面板 / 插件 / 语言**；设置项统一来自设置注册表（`kind` 只取控件输入类），落库只写 `app_settings`（**不新增库表**），插件经贡献点 `settingsSection` 增加设置项。见 `docs/spec/settings-standard.md`。
- **三份标准已定稿并落地**（2026-09，D61–D67）：控件 schema 规范（26 种宿主内置控件类型 + 校验分级 + 受控渲染骨架）、蓝图节点标准（10 种节点类型定义表驱动端口/解析/属性面板）、插件标准（manifest 类型化契约 + 贡献点 + 能力 + 宿主 API 版本）。**未完成的部分**：三种插件运行形态的执行体、控件 schema 的运行时通道接线（`wasm`/`dynamic-library` 两条通道与控件事件回传链）。

## 8. 命令与事件

- 核心域命令：`domain.action`，例如 `repo.open`、`source.scan`、`album.sync`。
- 插件命令：`plugin.{pluginId}.{action}`。
- 所有插件命令必须携带仓库上下文，并经过启用状态与能力授权校验。
- 长任务必须发出进度事件，支持取消；真实文件操作必须生成操作记录。

## 9. AI 打标

- AI 输入：文件 ID、图像访问句柄、模型/提供方配置、任务选项。
- AI 输出：tag、置信度、来源模型、生成时间。
- 回写：直接写入仓库 tag，但必须标记来源、置信度、生成时间。
- AI 结果**只写入自动组**（`file_auto_tags`），**不修改人工 tag**（D21）；自动组内高置信更新必须生成撤销记录。
- 第一期仅图片；视频 AI 打标延后（D17）。

## 9.1 视频与媒体能力

- 视频全格式播放：libmpv 跑独立媒体子进程（单实例常驻、崩溃自动重启）；播放画面嵌入面板（D14）。
- 视频元数据：全量媒体信息（时长/分辨率/编码/帧率/码率/音轨/字幕/章节），ffprobe 外部进程探测（D15）。
- 视频缩略图：扫描时同步生成首帧图，ffmpeg 外部进程批量抽帧（D16）；视频感知哈希复用首帧图像哈希（D12）。
- libmpv 与 ffmpeg/ffprobe 随应用捆绑发布。
- 媒体能力由 `hp-media` crate 承载（D19）。

## 9.2 色彩参考

- 自动提取调色板（**8 色色带**，随面板宽度） + 手动调整/锁定色值（**面板侧只保留调色板**，手动锁定暂无入口，见 D81）；点击色块在调色板下方显示色值并可复制（十六进制 / 十进制 RGB 可切换）；调色板由**全面分析**（源扫描 / **源全量重扫** / 右键「重新分析该文件」）**顺带提取并缓存**（缓存带格式版本、旧缓存自动重算；界面不再有"点击即提取"，见 D82）；仅图片（D18）。

## 10. 首期原型范围

- 单仓库 + 多媒体源。
- 覆盖：仓库创建/打开、媒体源挂载、图片+视频扫描/哈希、音频占位行、watcher+全量校验、固定/跟随相册（含媒体属性）、tag/评分、视频播放与元数据、色彩参考（仅图片）、文本类入库（`text` 媒体类型 + `book`/`document` 子类型，D93）与图书预览面板（卡片 / 列表 / 封面三视图，D94/D96）、基础面板、插件宿主骨架、AI 接口骨架（仅图片）。
- 不覆盖：音频完整索引（哈希/缩略图/预览/相似检索）、视频 AI 打标、绿色软件管理、文本正文查看器（epub / txt 预览，D94 明确延后）、跨仓库搜索、插件市场、完整签名体系。
