## 已确认但容易误解的点

- `tag` 统一替代原文档中的 `tap`。
- 内容哈希是身份；感知哈希只做相似/重复检索。
- 虚拟相册 = 成员关系 + 同步规则；固定型与跟随源型都落成员关系。
- 相册媒体属性默认 `multimedia`，但第一期音频不索引，故 `multimedia` 相册实际只显示图片+视频成员；`audio` 相册第一期无内容。此为已接受的连锁效应。
- 全局安装插件；按仓库启用；读写/高危能力按仓库授权。
- AI 结果直接写入，但必须标记来源、置信度、生成时间；高置信覆盖必须留撤销记录。
- 人工 tag 与自动 tag 关联表独立、tag 实体共用；同名可共存（D21）。
- tag 关系（层级/关联）为多父级 DAG，是关系图谱组件的数据源（D22）。
- tag 实体、关联与关系均按仓库独立（D23）。
- 「tag表」层级树中，多父级 tag 会在每个上级下重复出现，并以浅蓝色标示为交叉（D24）。
- 拖拽 tag 是**移动**（替换上级），交叉只能通过「新建同名 tag」建立（D24）。
- 面板最小尺寸只约束正文；标签条始终可见（D25）。
- 布局预设与仓库条目均支持右键管理；默认仓库在启动时自动打开并套用默认布局（D26）。
- 删除仓库不删除真实媒体源文件，仅删除注册与仓库库文件（D26）。
- 所有应用内系统文字必须走 i18n（三语键集一致），支持 `{name}` 插值；用户输入内容不翻译（D27）。
- 面板标签页标题在创建时计算一次，语言变化后必须显式 `setTitle` 刷新（启动时持久化语言为异步加载，晚于 dockview ready，需在语言就绪后刷新标题）。
- 蓝图只在其上叠加显隐/组收起/拉伸/方向行为；面板位置/大小/分组结构的**基准**仍由 `layout.*`（D1）管理（D29）。
- 蓝图中"组的隐藏" = 组最小化至 6px（标签条保留、组结构不删除），不是删除面板（D29）。
- 蓝图编辑器为**节点式（画布式拖拽连线，仿 ComfyUI）**，自 M6 阶段一落地；JSON 视图仅作辅助（D31）。
- **布局块 = 界面上的一个区域（栏）**，一栏内可堆叠一个或多个标签组/独立面板，它们同属这**一个**布局块（默认「媒体-测试」布局 = 左/中/右 3 个布局块）。
- 蓝图编辑器里**本节点只定"类型 + 自身必备字段"**，key 与 key 型引用由上级推导（用户不手填 key）；删除为**软删除**（关联节点保留、灰显「未接通」），未接通在服务端校验中是**软告警**、不阻塞保存。
- 蓝图面板是 dockview 面板、可被拖成**独立窗口**：凡"通知其他窗口""读取当前布局结构"的逻辑都必须走跨窗口共享或后端事件，不能假设同窗口可用。
- **D29 的"组拉伸 / 隐藏方向"运行时已实现（2026-09 增量）**：`blueprintLayout.ts` 的收起在指定 `hide_direction` 时按轴向几何找邻居（`toward:<组>` 经同层组映射解析），把本组沿轴压到最小、并把释放空间沿同轴放大到指定邻居；无法解析邻居时回退为"缩小本组、由网格吸收"。因此 D29 的验收条款（`A|B|C` 收起 B 方向向左→A 吸收 / 向右→C 吸收）已可运行。另注意：布局→蓝图的**自动同步**已按 D59 统一使用 `contains` 边（不再用已降级的 `memberOf`），并新增**设置开关（默认开）**。
- **蓝图侧的规范基线（2026-09 一致性整理）**：① 领域模型按职责分文件（`hp-core/src/blueprint.rs` 图文档 / `blueprint_types.rs` 取值域 / `blueprint_node.rs` 结构 / `blueprint_row.rs` 存储行 / `blueprint_validate.rs` **全部硬错误** / `blueprint_warnings.rs` 软告警 / `blueprint_migrate.rs` 迁移），前端 `packages/config` 同样拆出 `blueprintOverlay.ts`（浮层几何）与 `blueprintDefault.ts`（内置默认图）；② 桥接层 DTO **直接用 `hp-dto` 的类型**（`src-tauri` 依赖 `hp-dto`），不再在本层重复定义同形结构体；③ **写库一律走 `normalize_document`**：低版本迁移 + 补齐缺失的 `schema_version`，保证"文档内版本 = 列版本"（D58）；④ **对账只作用于当前层**（D51/D54）；⑤ `hide` = 收起（`setSize(PANEL_MIN_SIZE)`，网格约束下失败也**不关闭**面板），`toggle` 对标签组是收起/展开取反、`expand` 恢复**收起前记录的尺寸**；⑥ **装载即做解析层校验**（取值域/结构/版本闸门），无效则回退内置默认并**提示用户**；⑦ 引用候选（属性面板目标、工厂兜底上级）**按层过滤**，避免编辑器产出必被校验拒绝的跨层引用。原"仍未实现的三项"已落地（2026-09）：`hide_direction` 邻居吸收、`selection_change` 事件源与 `rating`/`has_tag` 的运行期 `context`、D59 同步开关（默认开）。仍为开放点：组位置 `x/y` 运行时语义、页面栈/返回语义与入口层选择，见 RFC 0007「实现期开放点」。
- **tag 库完整数据不随应用分发**：应用只内置轻量基底（实测 8,110 概念 / 12.07MB），完整词库（含全量 artist）为**按需安装的细分扩展包**（D36/D36.2）。未安装扩展包时功能仍可用但**覆盖率明显下降**，这是已接受的取舍，不是缺陷。
- **tag 库与插件系统的衔接已结案**（D36.1，构建时定案）：扩展包沿用已实现的 **`static-data`** 运行形态（**不新增 `data-pack`**），且**不声明能力与贡献点**（宿主读库、插件不直连数据库）。**启用语义也已结案**（**D36.9**，用户裁定）：数据包**无状态、安装即启用**，既不是应用级也不是仓库级启用——界面**不得**给它启用开关，「扩展」菜单把它列在**最底下**（只读行）。仍未结案的是**大文件安装方式**，见 RFC 0008「延后事项登记」。
- **tag 库扩展包按类型 + 细分命名**（D36.2 / D36.5）：**类型前缀**区分词典与关系——词典扩展 `tagdict-*`（按生态来源细分为 `tagdict-pixiv` / `tagdict-danbooru`），关系扩展 `tagrel-*`（`tagrel-games`）。目录名、插件 id、显示名三处都带类型前缀。包名必须具体简洁、对应内容，不用「字典」这类泛称。
- **tag 库的「层数」口径**（D36.3 / D36.7 / D36.8）：界面状态行的 `layers` = **内置基底 1 + 各扩展包各 1**，与插件安装了几个版本目录无关（只装配每插件的最新版本），也**不受 `plugins-dist/` 里放着多少可安装的包影响**。**未安装任何扩展 = `1` 层 / `8108`**（基底 `tag` 表 8,110 行 − 2 条重复概念身份）；四层全装（基底 + pixiv + danbooru + tagrel-games）应为 **4 层 / 304,575**。若在"未安装"时也报 4 层，说明装配层又把分发目录（`plugins-dist/`）当成了装配来源（D36.8）；若已安装时报 7 或 10，说明把同一扩展算重了（D36.7 的两条路径）。
- tag 库的**逻辑共享**（应用级参考数据，不随仓库隔离）与**交付方式**（不内置、按需安装）是两件事：前者已确认，后者的承载方式已定（D36.1）、安装通道待定。
- **库 2 与仓库级 tag 关系不可混用**（D34）：代码层用**不同类型名**（`LibRelation` vs `TagRelation`）与**不同表名**（`tag_relation` vs `tag_relations`）隔离，并有测试断言；库 2 是应用级只读参考关系，仓库级是按仓库隔离的用户可编辑关系。
- **`system` 不是 manifest 能自称的东西**：来源由宿主按安装方式判定，`system` 等级还必须持有主线仓库构建者签名（D38–D40）。manifest 的 `source.kind` 不参与信任判定。
- **控件 ≠ 面板**（**2026-09 由 D71 修订口径**）：**面板**是 dockview 承载单元（仓库/查看器/媒体预览…），是**可注册对象**（宿主 13 个 + 插件可注册）；**控件**是面板**内部**的 26 种宿主标准 UI 单元（**仅宿主可注册**，D62/D72）。**「浮动控件」这一概念已于 2026-09 取消**（原 D44/D49/D56）：浮在布局之上的一层显示改由蓝图 **`overlay`（浮层）容器**表达——它与布局块同级，直接 contains **面板**，并声明圆角/阴影/标签隐藏的**外观档位**；**不是独立窗口**。命名以 `docs/spec/control-standard.md` 与 `docs/spec/panel-standard.md` 为准。
- **Rust 走二进制、Python 走源码**不是双标：前者用户侧编译不可接受，后者由 Python 核心提供环境后无编译步骤（D38/D39）。
- 全部插件的分发策略与通道矩阵见 `docs/rfc/0009-plugin-distribution.md`。
- **界面（Interface）= 页面**：蓝图顶层节点 `interface`，一个界面即一个页面，可有多个，是后续多页面的基础；界面的直接子级是**布局块**与**浮层**（两者同级），面板挂在布局块/标签组/浮层之下（D47/D49；D50 修订）。
- **「界面跳转」是蓝图行为**（`navigate`，目标为界面节点），不是分支式脚本、也不由插件直接触发；插件只能触发事件，由蓝图规则决定是否跳转（D48）。
- **「控件」一词的含义已收敛**（**D71 取代原 D104 表述**）：蓝图侧一律叫**面板**（枚举 `control`；D46 的「面板控件」叫法已撤销），「控件」专属面板**内部**的 26 种宿主标准 UI 单元；蓝图原「类」改叫**类目**（枚举 `class`）。层级为 **界面/层 ⊃ {布局块 ⊃ 标签组 ⊃ 面板 ⊃ 类目 ⊃ 对象，浮层 ⊃ 标签组/面板}**（D46 经 D71 修订；D50/D51 补齐浮层与层的根）——**浮层与布局块同级且是容器**。
- **「与布局块同级」和「显示在布局块之上」是两件事**：浮层**归属**上与布局块并列（同为界面直接子级），**呈现**上以更高 z 序整体覆盖布局块；因此它不随面板/布局块关闭收起而销毁，不占布局网格，也不支持跨界面叠加（D49）。浮层之间的叠放由 `overlay.height`（1–10，默认 1，值大者在上）决定（D57）。
- **浮层就是容器，内容是面板**（2026-09 修订，D50；D56 已取消）：`interface --contains--> overlay --contains--> {面板, 标签组}`。**连接是显示的前提**：只有 `界面 --contains--> 浮层` 才表示"该浮层属于本页"，断开连接 = **未接通**（软告警、画布灰显），运行时会**收起**该浮层（关闭其内容面板）并**不再响应显示动作**，重新连上即恢复。`show`/`hide`/`toggle` 指向浮层 = 把它的内容面板以**浮动方式**显示/关闭（按 `size` 设置框体），并通知宿主刷新浮层容器。**相对定位**用九宫格锚点（缺省居中）+ 双模式偏移（`|v| ≤ 1` = 界面宽/高的比例、`|v| > 1` = 像素）；**尺寸** `size` 不写 = 默认最小 `240×160`，小于最小值夹紧；**外观档位** `shadow`/`radius`/`hide_label` 写在浮层节点上、只取宿主 token（不写死像素）。**初始显隐（`visible`）会在装载/套用布局/切层时对账一次**（幂等，且不会去关掉使用者布局里本来就有的面板）。**浮层容器本身的渲染**已于 2026-09 落地（`apps/desktop/src/app_ui/shared/overlayChrome.ts`）。
- **「层」是蓝图内部的画布/子蓝图**：一个层 = 一张画布 = 一个界面（页面），层名可自定义且**层名即界面显示名**；**一个蓝图仍只控制一个仓库**，跨层连接只允许 `navigate`（D51）。不要把"层"理解成界面内的分区或布局块，也不要把"分层"理解成多个蓝图。
- 层与界面是 **1:1**：`interface` 节点是该层的根，因此"跳到某层"与"界面跳转"是同一件事的两种说法（D48/D51）。
- **「图像源」现在叫「媒体源」**（D68）：只是**显示用语**变了，i18n 键名、面板 id、命令名与库表名都保持 `source`/`sources` —— 与 D71「面板」「类目」的处理口径一致，不要在代码或持久化结构里跟着改名。
- **添加媒体源只能"选取文件夹"，别名只能添加后改**（D68）：添加时不给别名输入框是**有意为之**，不要为了"方便"把它加回去。
- **进度浮窗的两条硬约束**（D69）：不定进度条只能动 `transform`（动布局属性会把 WebView 主线程打满，反而让进度事件进不来）；进度状态不许放进 `AppContext`（会把所有面板拖进每次进度的重渲染与重查库）。
- **卸载 = 完全卸载，不是"标记离线"**（D70）：卸载后**加回来也不会恢复 tag/评分**，这是用户确认的取舍，警告弹窗必须如实说明。底层 `unmount_source`（标记离线）只为历史离线行与恢复场景保留。

### 背景（对账得出的事实）

对账覆盖后端 **106** 条命令、文档 **88** 条、前端封装 **78** 条，以及文档 **19** 条事件。结论：

| D95 | **媒体预览不含文本类**：`file.query` 的媒体类型过滤由单值改为**集合** | 已确认（**已实现**，2026-10-08 用户裁决"媒体预览不包含 text 类型，text 类型在图书预览显示"） | ①**问题**：媒体预览的类型筛选里「全部」原来的口径是"**不筛**"（`mediaType: undefined`），而 `text` 自 D93 起**已进索引**，于是文本类会以"无缩略图的条目"漏进媒体预览；而它的筛选项只有 图片/视频/音频 三档、**筛不掉**它们（D94 当时把这一条记为待决项，不替用户决定）。②**口径（用户裁决）**：媒体预览与图书预览**互不重叠**——媒体预览 = 图片 / 视频 / 音频；图书预览 = 文本类。③**实现**：`file.query` 的 `filter.mediaType`（单值）→ **`filter.mediaTypes`（集合，缺省或空数组 = 不筛）**；面板侧「全部」= `["image","video","audio"]` 显式列出，图书预览 = `["text"]`。取值不在闭集内一律 `validation`（**不静默丢掉那一项**，否则"选了没生效"会被伪装成"筛出来是空的"）。④**为什么是集合而不是"排除 text"**：单值表达不出"面板的类型域是一组"这件事；用排除法还会让**将来新增的媒体类型默认漏进媒体预览**（例如日后加 `model`，媒体预览会莫名其妙多出它）。集合是**正向声明**，新类型默认不进任何面板，谁要谁显式加。⑤**SQL 形态**：集合 → **四个固定旗标**（与 `query_album_members_page` 同一手法），SQL 静态、参数个数固定，不必按集合长度拼 `IN (...)` 并把手写的 `?N` 编号整体挪位。⑥**相册同步收紧**：`AlbumMediaType::contains` 对所有取值（含 `Multimedia`）**不含文本类**——`Multimedia` 的含义是"图像 + 视频 + 音频"，不是"索引里的一切"；否则 `multimedia` 的跟随源相册会把文本文件写成成员，而 `query_album_members_page` 只认三个媒体字面量、永远列不出它们（"有成员但看不见"），卸载源的影响评估也会多算。⑦**连带口径**：媒体预览的档位清单收敛为 `mediaPreviewView.ts` 的 `MEDIA_TYPE_FILTERS` / `MEDIA_FILTER_TYPES`（唯一权威），工具条的 `<option>` **由取值域生成**而不是手写四个（手写时"加了档位忘加选项 / 加了面板认不出的档位"都不会被发现）；`imageviewer` 的浏览序列、`test_ui` 的取数一并改为集合写法。⑧**门禁**：`pnpm check:panels` 按**行为**断言"任何档位的请求集合都不含 `text`"+"「全部」= 三个媒体类型"+取数经 `mediaTypesForFilter` 映射（正向锚点），并断言 Rust 侧是集合语义、相册不含文本类。 |
| D96 | 图书预览面板视图修订：**原「封面模式」更名「列表模式」+ 重新定义封面模式 + 封面宽度滑条**（2026-10-09 用户口径） | 已确认（**已实现**，2026-10-09 用户裁决） | ①**现状与口径**：用户指出原「封面模式」"实际为列表模式"（封面在左、右栏填充剩余空间、一行一本）——**更名**为**列表模式**；同时**重新定义封面模式**：规则与列表模式一致，但**一行可展示多本**（网格），且右栏**不填充剩余空间**、固定为**封面宽度的 2 倍**（`BOOK_COVER_INFO_SCALE = 2`，单元格总宽 = 封面 + 10px 间距 + 2 倍封面，列宽固定不拉伸）。三种视图：**卡片**（封面在上 + 文件名在下，缺省）/ **列表** / **封面**。②**展示规则**（列表 / 封面两模式一致，共用一个 `BookRowInfo`）：作者行前加 **「作者：」**；简介**单独一行**、行首加 **「简介：」**（i18n 键 `book.authorLabel` / `book.descLabel`，不硬编码中文）；简介的**溢出标准 = 和封面图片底部齐平**——截断行数由封面高度推得（`bookDescLineCount(coverSize)`，信息列与封面同高扣掉文件名/作者/间距后除以行高，至少 1 行；行高参数与 CSS `line-height: 1.5` 逐项相等、只在 `bookPreviewView.ts` 定义一次），面板经 `--bp-desc-lines` 下发、CSS `-webkit-line-clamp: var(--bp-desc-lines)` 消费——封面变大简介显示更多行，**不再是写死的 3 行**。③**封面宽度滑条**：工具条新增与**媒体预览同款**的滑条（复用 `mp-size*` 样式类，min/max = `[96, 400]`、步进 8），拖滑条改**本会话临时覆盖**（与视图切换同口径），声明缺省才是"用户没动过"的值；三视图都用 `coverSize`。④**门禁**：`pnpm check:panels` 按**行为**断言三种视图取值域（`["card","list","cover"]`）、`bookDescLineCount`（随封面单调不减、至少 1 行、行高算术与 CSS 一致）、`bookCoverCellWidth`（2 倍封面算术）；源码锚点——简介 clamp **必须读 `--bp-desc-lines`**、封面网格列宽 `calc(... * 3 + 10px)` + 右栏 `calc(... * 2)` 且 `flex: none`、工具条 range 滑条带常量、信息三行共用 `BookRowInfo` 且带两个标签键。**回退即红**：clamp 退回写死的 `3` → 红；右栏改回 `flex: 1` → 红；标签键换成硬编码中文 → 红。 |
