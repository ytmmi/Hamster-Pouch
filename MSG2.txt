feat(mcp): 内置 MCP 服务（模型上下文协议）+ 新增第六个设置大类 mcp（D119）

一、新增能力
应用内起一个本机 MCP 服务，让外部 AI 客户端按标准协议读取 / 改写仓库数据。
- 形态：Streamable HTTP 单端点 /mcp（POST 收发 JSON-RPC 2.0、GET 开 SSE 通道、
  DELETE 结束会话）+ 免鉴权 /health 探活。
- 工具 26 个（16 只读 + 10 写）；每个工具都是对既有 #[tauri::command] 函数的
  直接调用，因此 MCP 与界面是同一套语义与错误串（不重写业务逻辑、不复制 DTO）。
- 安全边界：默认关闭、只绑 127.0.0.1、除 /health 与 OPTIONS 外都要
  Authorization: Bearer <token>（token 落 data/system/mcp.token）；写操作另受
  mcp.allowWrite 二次开关约束。
- 启停只有设置项一个真相：mcp.enabled 单一决定，setting.set 写入 mcp.* 后自动
  apply（幂等，配置没变不重启）；命令只有 mcp.status / mcp.reload 两条。

二、实现取舍
- 不引入 axum / hyper：根 workspace 连 tokio 都没有，桥接层的 tokio 只是 tauri
  运行时内部依赖。本服务单端点、请求体上限 8 MiB、并发个位数，用标准库
  TcpListener + 每连接一线程（非阻塞 accept + 20ms 轮询 + 15s 读写超时）足够。
  新增依赖为零——token 用两个 UUIDv4 拼接，JSON 用 serde_json，线程用 std。
- Handler trait 把传输层与 Tauri 解耦，端到端用例才能在真实 socket 上跑。

三、设置
- 新增第六个设置大类 mcp（SETTING_CATEGORIES 5 → 6、SettingCategory::ALL
  [_; 5] → [_; 6]）：mcp.enabled（switch，缺省关）、mcp.port（numberInput，
  缺省 57321）、mcp.allowWrite（switch，缺省关）。独立成大类而非塞进「界面」：
  它是外部进程接入本机数据的安全边界，需要独立入口让用户意识到这里在对外开门。
- 设置界面无需改代码（按 allSettingDecls() 渲染）；「全部设置 → MCP」底部新增
  服务状态块（运行状态 / 端点 / 令牌 / 工具数，端点与令牌可一键复制）。

四、端到端测试抓到并修掉两个真实缺陷（纯函数单测对此完全盲）
1. read_head 丢请求体：一次 read 会把头部与请求体前若干字节一起读进缓冲区，
   原实现只取头部文本、把尾部丢掉，随后 read_exact 永远等不到 —— 任何正常
   POST /mcp 都会挂住。修法：read_head 返回 (Head, leftover)，handle_post 先
   消费 leftover 再补读。
2. Windows RST 丢弃提前回包：接收缓冲区还有未读数据时 closesocket 发 RST 而非
   FIN，于是 401/404/405/OPTIONS//health 在请求体超过约 4 KB 时客户端看到的是
   ConnectionResetError 而不是那个清晰的 401（小请求恰好看不出来，所以此前所有
   用例都漏了；真实 MCP 客户端的 initialize 带 clientInfo/capabilities，一超
   4 KB 就命中）。修法：新增 drain_body()，在提前回包前按 Content-Length 把
   请求体读掉（上限 MAX_DRAIN_BYTES = 1 MiB）。回归用例
   large_unauthorized_body_still_returns_a_clean_401 已双向验证（撤掉修复即以
   ConnectionReset 失败）。

五、真实第三方客户端验收
以独立 MCP 客户端对 pnpm app:build 产出的 dev 包做真机连通：initialize 握手
（协议 2025-06-18 协商成功、只声明 tools 能力）→ notifications/initialized 回
202 → ping → tools/list 拿到 26 个工具 → 16 个只读工具逐个真实取数（含
file_query 游标翻页与 mediaTypes 过滤）→ 5 个写工具真实落库并撤销 → 业务错误

text/event-stream + 保活注释。37 项断言全通过。另核实 mcp.allowWrite=false 时
写工具回 isError:true「写操作未启用」、只读工具不受影响（重启后生效）。
